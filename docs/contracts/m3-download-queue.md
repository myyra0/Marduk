# M3-S01: recoverable download queue implementation plan

**Status:** Draft, not dispatchable. **Goal:** Turn a provider-approved artifact into a recoverable transfer and an identifiable downloaded archive, without installing a mod.

**Architecture:** Core owns transfer state, retry decisions and queue limits. Transport reads a reviewed source; storage owns private partials, durable checkpoints and archive publication. Provider authentication, metadata lookup and the optional install follow-up stay outside this packet.

**Tech stack:** Rust; M2 storage and archive admission; fake transport and clock for the deterministic contract. Select the HTTP client and freezes for production transport after its predecessor and dependency review. **Spec:** [integration contracts](../research/integration-contracts.md#downloads-and-versions--m3-s01s02s03-m4-s04), [effect trace](../research/headless-crosswalk.md#resource-and-effect-trace-downloads-and-installers).

## Shared boundary

| Operation | Inputs and result |
|---|---|
| `enqueue_download` | Reviewed `AcquisitionId`, approved `DownloadLocationId` and location revision → `DownloadId`, status. Core resolves the descriptor through the provider; no arbitrary caller URL, output pathname, or credentials enter the durable queue record. |
| `download_status` / `control_download` | `DownloadId` → authoritative snapshot; control also takes exact snapshot revision and `Pause`, `ResumeLive`, or `Cancel`. Duplicate delivery must not start another transfer; control cannot cancel once archive publication is claimed. |
| `resume_saved_download` | `DownloadId`, checkpoint revision, renewed request authority resolved by the provider → same record with a new active attempt or typed refusal. No saved grant by default; expiry or mismatch leaves the partial untouched. Live resume does not acquire a new attempt. |
| `discard_saved_download` | Exact `DownloadId` and checkpoint revision from a reviewed discard → tracked deletion of owned partial and checkpoint only; never a completed archive, active transfer, or another job's partial. |
| `downloaded_archive` | A completed record exposes `ArchiveId`, exact provider object, admitted digest, and verification level (provider hash checked when supplied, not implied by local digest). No partial can be returned as an `ArchiveId`. |

Ordinary states: `Queued`, `Receiving`, `Paused`, `AwaitingResume`, `Publishing`, `Ready`, `Cancelled`, and `Failed`. Live progress is not a checkpoint. Persist provider object, approved location identity, owned partial reference, known total, validator and committed offset. Flush the partial before committing its checkpoint; if reopened length exceeds that offset, only truncate the tail after identifying it as the same manager-owned file. A shorter length is not resumable from the recorded offset. A path on a substitute drive is `LocationUnavailable` and is never repaired or discarded by name. Rehash retained bytes before completion rather than trusting a serialized hash state.

For append, check the same provider object and an approved representation validator, identity encoding, and one `206` range starting at the committed offset with compatible total, end and body length. A strong matching ETag is the initial proof route. The reference also tries a date validator; leave date-only and validator-less safe resumption open for provider qualification, with restart from zero on the same reviewed object when append cannot be justified. If that would remove an actual supported resume route, present the decision before closing parity. A `200` response to a range request is a fresh body, not a suffix; use a new private partial. Reject malformed `206`; do not treat `416` or the validator alone as evidence the complete file is present. A changed provider object or changed authoritative digest requires re-review, not a transparent restart.

The [HTTP evidence](../research/provider-upstream-review.md#shared-checks-that-remain-open) excludes weak ETags from `If-Range`. A date is eligible only where there is no entity tag and it is proven strong for the representation. Do not compare cached catalog dates or assume equally spelled ETags at different, unqualified CDN origins identify the same bytes. Follow only a provider-approved redirect route; reconstruct each request with its allowed authority, never copy auth headers or a private query from the previous request to a new origin.

Validate final length against authoritative exact byte size when available, check supplied provider hashes, and admit the archive through M2-I01 without activation. Approximate size listings are not exact checks. Prepare admitted bytes privately, then publish the archive reference and provider provenance together in one catalog transaction only after bytes are durable. A failed or lost reply never produces a second archive or an installed mod. During receipt, **Cancel** stops and discards the managed partial, matching the traced Nexus route; a crash or transient failure may leave a resumable checkpoint. Canceling a browser watcher does not delete its external file (M3-S02).

Persist the user-facing download-only preference alongside queue settings. The queue always ends at `Ready`; the calling workflow may offer or continue a separately reviewed install only when download-only mode permits it. A preference change never retroactively authorizes publication of a mod.

The [downloaded archive management trace](../research/headless-crosswalk.md#resource-and-effect-trace-downloaded-archive-management) also constrains location/visibility edits, reviewed move/removal, and batch controls for this packet. Keep location and visibility edits metadata-only, and bind archive/sidecar identity and destination revision for move/removal. Freeze the native cross-location transaction and recovered-status contract separately from a transfer checkpoint; receipt and publication do not authorize relocation or deletion. If a moved artifact survives a later metadata or batch failure, report it as moved and recover the remaining effects without recopying it or changing an installed mod.

The [desktop cleanup trace](../research/desktop-action-ledger.md#cleanup-and-operation-history) adds a read-only inventory and a separate reviewed selected/all cleanup. M3-S01 owns download/cache protection and effect results, M4-S03 owns list-store cleanup, and M4-A03 presents the aggregate result without doing its own filesystem writes. Distinguish explicit Discard of a named saved transfer from automatic orphan cleanup. A name, age or absent live row is not ownership proof.

The [Downloads row trace](../research/desktop-action-ledger.md#download-rows-location-settings-and-transfer-controls) separates visibility, explicit archive installation, Move/Remove and saved Resume. Resume completion only publishes the archive; M3-I02 owns target rechecks when the user later chooses to install it. Keep Move/Remove scoped to reviewed file and location identities with explicit collision decisions and item results.

## Worker boundaries and proposed commands

1. **Queue and oracle.** `crates/core/src/downloads.rs`, `crates/core/tests/download_resume.rs`. Freeze core request/result types and stable outcomes (`StaleCheckpoint`, `LocationUnavailable`, `RenewalRequired`, `ObjectMismatch`, `RangeRejected`, `VerificationFailed`) after M2-I01 provides the archive/location interfaces. Planner owns the named fixtures below; prove wrong implementations fail before writing the queue. Shared cap is aggregate across active transfers, not per job.
2. **Transport.** `crates/sources/src/download_transport.rs` implements the reviewed acquisition and stream response boundary. Transport does not choose archive names, install mods or expose URLs/headers in logs. Freeze source-specific validator rules with provider evidence, not an undocumented interpretation in a generic worker.
3. **Partial and catalog store.** `crates/storage/src/download_store.rs`, `crates/storage/tests/download_store.rs`; freeze migration ordinal against the predecessor. Use qualified location handles and existing private-stage publication, not an arbitrary browser folder as a writable cache. Sol reviews the checkpoint/publication order. No tool or source consumer directly changes queue files.

## Planner witnesses

| Planner witness | Fixture and assertion |
|---|---|
| Test fixture scope | Use `abc`/`abcdef` as transport bytes with a recording admission fake. The storage suite also uses a real synthetic ZIP from M2-I01 so that successful stream assembly alone cannot qualify archive publication. |
| `resume_appends_only_to_the_reviewed_representation` | Prefix `abc`, offset `3`, total `6`, strong validator `"v1"`; range `3-5/6`, identity encoding, body `def` completes exactly `abcdef`. Wrong range start, length, validator, or object never appends. No `ArchiveId` while incomplete. |
| `weak_or_out_of_scope_validator_cannot_authorize_append` | Saved `abc` has weak `W/"v1"`, or a strong tag only valid at origin A and redirected to unqualified origin B. No `If-Range` with that validator, no credential forwarded and no append. A fresh transfer of the same reviewed object needs valid request authority; stale partial bytes remain unchanged until safe replacement/discard. |
| `full_response_restarts_without_concatenating` | With the same prefix, `200` body `abcdef` for the still-reviewed object completes from a new private partial. Result is six bytes, not `abcabcdef`; no second visible archive on replay. |
| `restart_uses_durable_offset_and_held_location` | Persist `abc`, then write `XX` without a checkpoint. Restart resumes at `3`, not `5`. Repeat with a short partial or substituted location identity: no append; substituted-volume sentinel untouched. |
| `live_pause_cancel_and_interrupt_are_different` | Pause/resume keeps one transport attempt; process interruption later yields a saved checkpoint. Cancel before publication removes only that attempt's owned partial/checkpoint, and old job control cannot resume an interrupted attempt. |
| `ready_requires_provenance_and_verification` | Inject an exact hash mismatch and then a crash between private payload durability and catalog commit. Neither creates a visible archive. Lose reply after catalog commit under download-only mode: reconnect sees one `ArchiveId` with exact provider provenance; no install follow-up and profile revision unchanged. |
| `two_transfers_obey_one_rate_limit` | Fake clock, 4 bytes/second, zero initial byte credit, two 4-byte bodies. After one elapsed second at most four bytes across both; after two, both finish with no stalls in the no-failure fixture. Pause one and check active peer can use the available budget. |
| `cache_cleanup_preserves_active_partial_and_required_recovery` | One disposable managed entry, active and resumable partials, a required journal input, and an unowned user download. Sizing is read-only; Clear removes only the reviewed disposable entry. On new lease, replaced root or deletion failure, report retained/blocked/failed truthfully and do not mutate the other files. |

Future checks: `cargo test -p marduk-core --test download_resume`, `cargo test -p marduk-storage --test download_store`, plus the separately approved real-location checks on both platforms. Exact transport checks and nominal queue/concurrency bounds must be frozen before dispatch. Provider credentials and real network use remain behind G-EXT; those do not block an approved offline fixture.
