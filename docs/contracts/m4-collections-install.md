# M4-S01: Collections install and ownership brief

**Status:** Draft, not dispatchable. One orchestrator owns the lifecycle, not authoring or provider transport. Use the [pinned effects](../research/headless-crosswalk.md#resource-and-effect-trace-collections-and-wabbajack) and [shared integration rules](../research/integration-contracts.md#collections-and-lists--m4-s01s02s03). Keep Rust-first and reuse M3 download, installer and profile-group contracts. Do not write a second installer.

## Reviewable operations

| Operation | Inputs and resulting authority |
|---|---|
| `inspect_collection` | Exact source domain/slug/revision or admitted local package ID/digest, plus target game identity. Return supported manifest, warnings, known manual inputs and per-file identity, or typed unsupported/wrong-game refusal. “Latest” must resolve to an exact revision before review. Collection-format imports and direct bundled profile imports keep separate identity/provenance; PROF-03 does not require the reference's private export format. |
| `preview_collection` | Inspected package ID, `DownloadOnly`/`Standalone`/`Append`/`Update`, exact target instance and applicable profile/collection revisions, optional choices and per-item collision choices → immutable `CollectionPlanId`. Show required, optional, bundled, offsite and provider-backed inputs; paths, authored mod/plugin order, INI/options/patch effects, omitted content, and ownership changes. Binding a different game build or accepting an allowed mismatch requires a new review. Download-only has no profile effects. |
| `apply_collection` | Exact reviewed plan ID → recorded operation. Validate identities and expected revisions again under the relevant leases; claim the same plan at most once. For a new standalone install, reserve a dedicated profile and show incomplete state until all required effects are verified. No incomplete profile can be deployed as a completed collection. |
| `resume_collection` | Existing operation/installed ID plus recorded state revision → continuation of the same target revision or typed refusal. Check persisted plan, exact linked artifacts, installed steps and latest prompt. An interrupted update is not a first-install resume, and cannot silently switch to a different target revision. For appended records, bind host profile, installation ID and original update/append mode; never discover the host by slug alone. |
| `plan_collection_change` / `apply_collection_change` | Exact installed ID/revision and typed `SetEnabled`, `ResetAuthoredOrder`, `GroupWith`, or `Remove` intent → reviewed plan/effect result. Bind group/linked profile revisions and relevant deployed generation if applicable. Report change, retained entries and blockers by stable identity; never map a group selection to an arbitrary member. |

Open/blocked, preparing, awaiting input, interrupted, complete and recovery conflict are distinct. Persist prepared, applied and verified effects under an operation ID; a reply, visible filename or progress message is not a commit. Reuse M3-I02 prompt IDs/revisions. A required manual archive cannot be skipped; an allowed optional skip is recorded in the plan. Keep verified downloads on interruption. Keep pending effects private or otherwise visibly incomplete, and retain the previous committed revision and installed membership while an update is pending. Only finalize once all required effects pass verification; once published, cleanup cannot retire unrelated revisions.

The [desktop route](../research/desktop-crosswalk.md#collection-install-and-removal) exposes appended resume and revision changes through a bound detail view. Preserve that outcome in the desktop client, including an explicitly selected different (not necessarily newer) revision. Headless reference resume/update is standalone-only; adding a new headless route is not needed for parity. Keep `Append`, resume of incomplete append, and update of an existing appended record distinct in the review. Check the exact selected host, group lock and deployment revision; do not make an ambient profile selection the authority for an effect.

The [public read schema](../research/provider-upstream-review.md#nexus-collections--m4-s01s02) lets discovery request latest published; bind the returned game, collection and exact revision before planning. A GraphQL response with missing/error-affected critical fields or a different returned revision cannot yield an install plan. Do not implicitly override content preferences or resolve latest again on resume.

## Ownership and proof

Record the exact installed revision, member reference, introducing operation, and current owners. A reused/personal member is not introduced content; ambiguous origins are retained. An appended collection may toggle only its introduced, exclusively owned membership; its removal releases ownership and removes only an eligible member, not another collection's or profile's reference, the host profile, or downloaded archives. Re-review deletion if a new reference or external edit changes the removal plan. A standalone collection Remove is a reviewed **profile removal** through M2-P01, not appended-removal logic. Show that scope and retain recovery evidence for any affected deployment. Authored-order reset changes mod order and game-content plugin order independently, not source bytes; exact treatment of extras and locks must be pinned separately for standalone and groups.

| Planner case | Fixture and exact result |
|---|---|
| `download_only_leaves_profile_unchanged` | Required Nexus and pinned Thunderstore artifacts become exact-provenance downloads; offsite/manual work is listed separately. Profile P revision 8, its bytes and memberships remain unchanged. |
| `manual_required_file_cannot_be_skipped_or_swapped` | Required file ID `41`, optional `42`. Skip `41` or submit `42`/wrong digest under `41`: no advancement. Explicit optional skip only affects `42`. Submit the correct `41` to the current prompt, then recover after a lost reply; no second install. |
| `interrupted_update_preserves_committed_revision` | Installed revision 1 has `[personal, old]`; preview revision 2 replacing `old` and adding `new`. Interrupt after first verified private output: revision 1 and its exact bytes remain authoritative. Resume revision 2, not latest revision 3; success updates the recorded generation once and retains `personal`. |
| `appended_revision_change_binds_host_and_install_id` | Host A has primary P and appended X at revision 4; B also has X but with a different install ID. Open A's appended detail and review revision 3. Interrupt, switch selected host, or reuse a stale record: no retargeting to B or primary P. Resume the reviewed A/revision 3 only; required-input failure cannot retire old X or shared/personal files. A fresh review can select a different revision; Download-only leaves every profile unchanged. |
| `append_removal_retains_personal_shared_and_uncertain` | Appended set owns `exclusive`, reuses `personal`, shares `shared`, and lists an uncertain `unknown`. Disable only `exclusive`; removal preview deletes only it. Add a sibling reference before Apply: stale plan, none removed. Re-preview and remove the set; all four members' payloads now remain referenced or retained. |
| `groups_and_resets_use_bound_authored_order` | Install standalone set with authored mods `[A,B]` and plugins `[Q.esp,P.esp]`; place profile in group G with a sibling S. Reset the reviewed authored portion to those exact orders, retain S-only items without rewriting S, refuse a stale or locked group. Freeze any edition-specific plugin policies before dispatch. |
| `first_install_does_not_complete_with_missing_required_effect` | Interrupt with one required archive or declared required transform unverified: no ready or deployable set. On correct replay, identical manifest and selected output digests to a clean run. Optional or warning-only effects must be explicitly classified during manifest evidence freeze, not guessed by a worker. |
| `latest_is_discovery_not_install_authority` | Latest published resolves to revision 7. Later discovery returns 8, but Apply and resume target reviewed 7. Exact lookup returning 8, a different game, or HTTP `200` with errors affecting revision 7's required metadata yields no newly admitted package or profile effect. |
