# M3-S03: Thunderstore and Hexium dependency plans

**Status:** Draft, not dispatchable. One orchestrator owns two repository adapters and one dependency plan; reuse the [download queue](m3-download-queue.md), [installer plans](m3-installer-sessions.md), and version operations in [M3-S02](m3-nexus-and-versions.md). Provider-specific identity is not a domain mod ID. Source evidence: [account and version trace](../research/headless-crosswalk.md#resource-and-effect-trace-provider-accounts-and-versions), [download and installer trace](../research/headless-crosswalk.md#resource-and-effect-trace-downloads-and-installers).

1. **Catalog and normalization:** `crates/sources/src/{thunderstore,hexium}.rs` and `crates/sources/tests/repository_catalog.rs`. Key `RepositoryPackageKey` by provider/community/namespace/package; full artifact identity also includes exact version. Preserve source-specific catalogue filters, pagination, unavailable/retired releases and Hexium's prerelease recommendation setting. Do not treat a stable recommendation as a ban on a specifically selected, supported prerelease. Cache entries by repository/community; partial or stale data remains visibly stale. SHA/storage digest, expected manifest/package identity, and byte count are separate checks. Name and size alone are not trusted provenance.
2. **Plan and commit:** `crates/core/src/repository_plan.rs`, `crates/core/tests/provider_dependencies.rs`. `preview_repository_install(profile, revision, package, choices)` freezes a dependency-first graph, selected versions/metadata, affected owners and per-item `Install`, `Replace`, `Enable`, `Satisfied`, or reviewed `Skip`. Preserve user-selectable dependency scope. A required dependency intentionally left unsatisfied must be shown separately from verified completion; freeze UI decision and allowed override cases before dispatch. Distinguish Hexium fallback to a pinned Thunderstore dependency from replacing an installed mod's current source; one approval is never evidence for the other. Revalidate before any publication and claim exact plan ID; effectful children use the normal installer and immutable revision protocol. Confirmed dependencies are acquired and published individually; return completed/failed/unstarted, stop on unsafe rollback. Never substitute repository, version or affected profile on retry.
3. **Shares, links and fixture boundaries:** preserve published list/share acquisition and exact source linking, including Hexium archive handoff into reviewed profile import, not an implicit install. Profile import format/generator belongs to M3-P03/M4-S01 as applicable; domain and routing cannot be inferred from display names. Confirm where profile sharing, source identification, installers for direct dependencies and applicable protocols are actually reachable before freezing external contracts. Freeze exact types and paths against predecessors; `cargo test -p marduk-sources --test repository_catalog` and `cargo test -p marduk-core --test provider_dependencies` are planned offline commands, not live proof.

Prefer the documented community listing-index shape where qualified: bound decoded bytes, chunk count and concurrency, validate chunk origins under provider policy, and activate only a complete normalized snapshot plus its validator. A failed chunk retains the last successful snapshot as stale; a `304` is useful only for that exact complete cache and scope. [Thunderstore documents conditional dates](../research/provider-upstream-review.md#thunderstore-and-hexium--m3-s03); qualify Hexium behavior separately. A share retrieval key may resolve a profile archive for review; generating a share by sending bytes to `/create/` is a separate remote effect, not part of read/import.

## Desktop selection and dependency scope

- `gui_qt/thunderstore/version.py:83–121,123–174` lists versions using the installed mod's repository/community, orders parsed versions, and distinguishes Reinstall from a different version. `gui_qt/app.py:5231–5284` captures the originating game/profile and owner for replacement. A catalog lookup, explicit row selection and signed-off replacement are separate; changing the active view cannot rebind an old row.
- `gui_qt/app.py:4851–4914,4916–4953` reviews repository fallback or replacement source changes before offering extra dependency selection. `gui_qt/thunderstore/dependencies.py:71–118,146–193` lists source, conflict choices and estimated bytes, supports Select all/Skip all, and returns selected dependencies in resolved order followed by the requested root. Skip all means root-only when allowed, not cancel or satisfied dependencies. An unresolved graph is still a distinct refusal.
- `gui_qt/app.py:6042–6078,6121–6150` reuses that chooser after linking/identifying an existing mod, but the root is only context in these routes. Cancelling or skipping all extras must not reinstall it, undo the completed link, or call the download queue. Confirming extras uses each reviewed dependency identity, not the root's source or current active profile.

## Planner witnesses

| Future case | Distinguishing result |
|---|---|
| `community_and_prerelease_policy_are_not_global` | Same namespace/name appears in Hexium community A and Thunderstore community B, with stable `1.2.0` and `1.3.0-rc.1`. Toggling prerelease recommendation affects the applicable provider only; selecting version on A does not download hash from B. |
| `fallback_and_source_switch_require_distinct_review` | Hexium root has a dependency satisfied only on Thunderstore; one installed module has another source. Authorizing fallback alone does not allow replacing that module's source. Separate accepted review binds both exact objects; if metadata changes, no new publications. |
| `cycle_and_unreviewed_missing_dependency_cannot_publish` | `A → B → A` refuses plan; missing B becomes explicit unresolved. A skip requested for C cannot suppress the diagnostic for B. Accepted deliberate skips (where supported) are reported as skips, not satisfied dependency installations. |
| `partial_install_reports_verified_items_and_does_not_replay_them` | Dependency B commits before A, then A fails pre-commit. B stays recorded; A keeps prior revision. Reconnect states partial result and does not repeat B. If B was already installed and healthy, plan marks `Satisfied`; a disabled equivalent produces `Enable`, not a redownload. |
| `share_and_source_candidates_do_not_attach_by_display_name` | Two namespaces return package `Example` and same archive display name. Identify lists both; only reviewed exact choice attaches provenance. Acquiring a compatible share code returns a reviewed-import artifact without modifying profile revision. |
| `catalog_refresh_is_atomic_per_repository_and_community` | Cache complete Thunderstore community A at `T1`. Refresh from two chunks at `T2` with one invalid/over-budget chunk: A retains T1 rows and validator and is stale; B and Hexium are untouched. A retry with both chunks promotes T2 once. A subsequent same-scope `304` reuses T2; an unsolicited `304` without complete cache publishes nothing. |
| `share_read_never_creates_remote_share` | Hexium share GET returns valid, then malformed archive bytes in separate cases. First yields an admitted artifact awaiting profile review; second yields no import. Neither sends a share-create request or changes the profile. |
| `repository_quick_update_survives_unavailable_nexus` | In a mixed selection, Nexus sign-in fails. The eligible repository queue still runs against its original profile and exact reviewed successor. Switching the displayed profile cannot retarget or silently reapprove that queue. |
| `dependency_picker_keeps_requested_and_existing_roots_distinct` | Use the same dependency fixtures with a newly requested root and a previously linked root. Cancel produces no new work; allowed Skip all queues only the new root, and queues nothing for the existing root. Select one dependency and verify its exact repository/version, the projected byte total and dependency-first order; changing the originating revision invalidates the review. |
