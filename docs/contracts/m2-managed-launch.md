# M2-L01: managed launch and process ownership brief

**Status:** Draft, not dispatchable. One orchestrator owns this packet. Consumes the checked installation/profile identities from M2-G01 and committed deployment plus resource leases from M2-D01. Private-view implementation belongs to M4-X01/X02, runner/prefix mutation to M4-Y02, and tool-specific execution/output to M4-Y03/Y04. See [pinned launch traces](../research/headless-crosswalk.md#resource-and-effect-trace-launch-wine-and-game-configuration) and [platform evidence and route gates](../research/launch-tool-upstream-review.md).

**Recommendation:** One launch module with a small review/dispatch/observe/stop interface. Direct routes and external-launcher handoffs are different adapters; do not reduce both to “spawn and wait.” A direct-only interface loses supported store or launcher behavior; an open-ended command or wrapper interface loses precise identity and effect control. Do not add a resident helper or unprivileged process supervisor until the route matrix demonstrates a safety or compatibility need.

| Operation | Draft contract |
|---|---|
| `preview_launch` | Review exact plan mode `UseCommittedDeployment`, `DeployThenLaunch` (only where supported), or explicit `LaunchWithoutDeploy`; exact active references, committed generation if relevant, destination/view, executable or registered launcher entry, arguments, cwd, environment, runtime/prefix and effect list. Distinguish starting from an existing runtime versus downloading, updating, initializing or temporarily restoring. No command or update during preview. |
| `apply_launch` | Claim reviewed submission once; lock all affected deployment/view/prefix resource identities, not just a game name. Recheck identities/fingerprints, prerequisite effects and ownership before dispatch. Record dispatch intent before the external call. On an interrupted or uncertain call, reconcile observation; do not retry by spawning again. Conflict or inaccessible prefix/view reports an actionable refusal, never an automatic fallback. |
| `launch_status` | Separately expose dispatch, observed liveness, owner/stop availability, approved-view visibility proof where applicable, and cleanup/recovery. A successfully resolved wrapper isn't necessarily a running game. A launcher callback is not proof the approved files are visible. Missing or stale observations never authorize destructive work. |
| `stop_launch` | Check exact launch ID/current observation and ownership. Return an accepted/requested stop versus confirmed exit. Never act on a name, a guessed PID, a whole shared prefix, or an external launcher session without proven authority. If a retained route can't satisfy safe Stop, keep the proof gate open and bring the compatibility decision back. |

Persist and reconcile the launch reservation independently of the dispatch job. If the manager or either client exits, stop, detach and crash behavior are **not** interchangeable: adjudicate visible behavior per route before choosing lifetime controls. After restart, rebuild liveness from trustworthy observations; retain unresolved leases for potentially live users of mutable/private roots. Release only after confirmed quiescence and successful cleanup/recovery, not on a timeout alone. Treat a reservation whose dispatch was definitely not reached separately from one with unknown external outcome. Root ownership and recovery remain authoritative even if presentation history is pruned.

## Planner acceptance and ownership

| Witness | Distinguishing result |
|---|---|
| `launch_mode_binds_committed_generation` | A is deployed while B is selected. Applying B as `UseCommittedDeployment` fails with no process. Explicit no-deploy follows its reviewed semantics without changing A, or reports a route conflict; it does not silently inherit A's private view. Changing the committed generation after preview invalidates Apply. |
| `uncertain_dispatch_is_never_replayed` | Inject two cuts: durable reservation before any dispatch, then after child/launcher accepts but before receipt is saved. Reconnect with the same submission. First is provably unstarted; second is observed or remains unresolved, with exactly one original external call and no second spawn. |
| `early_wrapper_exit_keeps_view_reserved` | Inert wrapper exits while child still uses the view. Hold scope even if terminal event is lost. An unmanaged same-name process never receives Stop. On restart re-observe the actual managed child where possible; inability to re-establish ownership leaves a visible unresolved state, not forced release. |
| `prefix_rebind_or_busy_refuses_setup` | Rebind reviewed prefix/runner between preview and apply, or occupy it from a sibling profile while a route wants to initialize or update. No mutation, fallback prefix, or broad stop. Reuse this shared gate for Wine prefix setup/repair in M4-Y02. |
| `package_handoff_denial_never_launches_public_fallback` | Adapter can open an external launcher but the child lacks the checked view role. Return exact route/permission gap; don't start against the real install, acquire blanket permission or clean an uncertain view. |

Core owns `crates/core/src/launch.rs` and prospective `crates/core/tests/managed_launch.rs`; platform owns native spawn and launcher observation in the platform adapter; storage owns reservation records and recovery evidence. Freeze exact types, owned files/fixtures and commands against the predecessors, then review retention and recovery with Sol. A fake route tests the portable contract. M2-A01 and M4-A03 qualify installed-package handoffs; M4-X01/X02 verify actual private visibility, tool output isolation, and retained behavior per applicable route. These name intended checks; they are not runnable product tests today.
