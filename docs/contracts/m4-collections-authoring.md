# M4-S02: Collections authoring and publication brief

**Status:** Draft, not dispatchable. One orchestrator owns local authoring and remote release actions, not installation. Follow [desktop evidence](../research/desktop-crosswalk.md#collection-authoring-and-remote-visibility), M4-S01 manifest guarantees, M3-P03 profile export boundaries, and G-EXT. Keep local authoring usable without credentials.

1. **Draft and package:** `crates/core/src/collection_authoring.rs`, `crates/archive/src/collection_package.rs`. `preview_collection_export` binds the profile/content revisions and reviewed per-mod choices (reference, bundle, patch, installer choice, omit), notes, dependencies, rules and authored settings. Report the actual bundled files and proposed metadata, missing archives, inclusion/redistribution blockers and unsafe or ambiguous changes. `build_collection_export` consumes that exact plan and returns checked immutable package identity/digest. Local draft autosave, export, and offline validation perform zero provider writes. Freeze export format with evidence: external Nexus schema interoperability is separate from compatibility with private reference data.
2. **Remote drafts:** `crates/sources/src/nexus/collection_authoring.rs`. `plan_collection_upload` binds package digest, account, game domain, explicit `CreateDraft` or `NewDraftRevision(collection ID)`, and expected remote state. `submit_collection_upload` returns an operation record and eventually the exact draft ID/revision, not “published.” If the selected collection disappeared, offer a separately reviewed new draft; do not make a different target look like the reviewed update. Bind retry to the same draft target and bytes. If provider registration outcome is unknown after loss of reply, reconcile against remote identity or stop for operator review; do not guess or repost.
3. **Author's collection management:** same source and core boundaries. List own collections/drafts, install the newest published revision or the available draft when no published revision exists, edit metadata/changelog with exact resource/version, separately confirm publish of the exact draft with listing/adult choices, and apply a separate listing change to an existing published collection. Install through M4-S01; directly selecting a draft alongside an existing published revision is not established by this route. Use provider-returned state as authority. No publication from autosave, package creation or draft upload. Freeze provider capability and confirmation wording before the client subtask; avoid adding a new headless route merely because the desktop action exists.

The [upstream policy review](../research/provider-upstream-review.md#nexus-collections--m4-s01s02) requires a separate allow/refuse decision for Nexus upload, including private drafts. Show the entries and eligibility evidence before any upload; no actual mods/mod files as bundled assets, and no uncertain-rights resource silently approved. An ineligible local package can be revised for Nexus without changing its local draft or disabling lawful local authoring. API visibility is not upload or publication permission.

Qualify the revision route before selecting it: `NewDraftRevision` never authorizes replacing an existing draft, including one created between review and submission. A read-before-write check alone does not make a provider upsert create-only; if no qualified route can honor the reviewed effect, stop and bring back the evidence rather than picking a new behavior. The pinned client may also rename the parent collection before registering a new revision. Retain the rename outcome as an explicitly reviewed metadata effect, with its own result if registration then fails; no hidden rename in a draft-only plan.
