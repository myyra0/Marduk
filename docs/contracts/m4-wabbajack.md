## Operation and ownership boundary

| Operation | Inputs and effects |
|---|---|
| `list_gallery` / `acquire_list_package` | Select cache-only/refresh, then exact gallery ID and advertised version. Check the advertised size/hash when present and admit to private package storage. Cache changes are allowed; no profile changes. Local package intake has the same inspection boundary, without gallery provenance. |
| `inspect_list` / `preflight_list` | Admitted package ID/digest, `New`/`Resume`/`Repair`/`Update`, installation revision if existing, selected profiles, bound game/source and cache roots, setup/fixes/cleanup choices → `ListPlanId` and categorized checks. Report missing manual inputs, known issue acknowledgments, working-space needs per role, game source fingerprints and the exact possible writable roots. Preflight must not publish a profile, execute setup, or move user content. |
| `import_list_archive` | Exact reviewed package/plan and expected manifest hash/size, selected local file → verified cache reference. Stream to an owned stage, recheck exact fingerprint and applicable format/size bounds, never delete or modify the selected source. No package install is authorized by import. |
| `apply_list` | Exact reviewed `ListPlanId` → durable operation. Bind conflict choices `KeepLocal`/`UseAuthor` to each reviewed path and observation; no choice means no write to a conflict. Retain supported three-way merge by staging and reviewing merged output, never overwrite silently on merge failure. Apply required setup and authored profile/link state before reporting ready. |
| `resume_list` | Exact operation, package digest, plan state and bound roots → continuation, waiting for inputs or typed refusal. Reuse a completed output only when its directive/input/context signature and durable output digest match. A repair rechecks the current installed revision; update targets an explicitly newer or different reviewed package; resume keeps the interrupted target. A different package with the same title is not a resume. |
| `reset_list_order` / `remove_list` | Reset authored mod and game-content order on an exact referenced profile, keep user-added entries and report them. Removal previews installation ID/revision, linked profiles, groups, active deployment, and retained content. Refuse locked/substituted targets. Restore affected managed deployments before releasing references; failure blocks removal with its evidence intact. No delete-by-title. |

Use four distinct roles: read-only real game input, verified archive cache, private reconstruction/output, and managed list installation with bound profiles. **Stock Game is an owned output tree, not permission to update the original game.** A later launch consumes an explicit Stock Game identity, never silently falls back to the real game if unresolved. Retain writable tool-output isolation and setup prerequisites independently of successful reconstruction. Source/manifest strings never authorize redirects, executing a tool, root relocation, or broad deletion. Hosts for HTTP/CDN, Google Drive, Mega, MediaFire, ModDB, Nexus and conditional LoversLab, plus local/manual and game-file sources, need individual route/format/terms evidence; neither silently drop an established host nor treat it as safe because it has a registry entry.

Keep output ledger, installed generation and pending decisions separate. A pause/cancel before committing may retain verified download/cache and owned work, as in the reference; it does not mark the list ready. No cancel during a journal step that cannot be safely paused. Existing list remains on its committed generation until the new output and its profile links are durable; no ready state for unresolved required files, incomplete setup, or development-only omission of game files. Preserve unowned or user-edited data on repair/update/removal. Retain the reviewed clear-archives option with exact owned-cache cleanup and shared-reference checks; changing the scope of existing supported cleanup routes requires a user decision. Preview any selected profiles' Overwrite cleanup per path (keep vs authored/clear), not a default blanket deletion.

## Directive witness map

Use small inert fixture inputs. For byte transforms, pin expected output bytes or an independent fixture digest before worker dispatch; do not generate expected values with the implementation under test. Game-specific fix/task outputs and runtime-only behavior are separate from the nine manifest directives.

Use the [pinned upstream DTOs and Linux x64 build](../research/provider-upstream-review.md#wabbajack--m4-s03) as comparison candidates, not shipped dependencies or proof targets already met. Classify additional upstream discriminator names by manifest/wire version and execution role. An unclassified required reconstruction input blocks before writes; implementation-only/compiler metadata may be ignored only with a recorded format witness. Fix a provider-format hash vector and separate local output digest vector. Compare inert fixtures on both platforms after approval; still verify actual list setup, game folders and launch separately.

Do not impose one output-hash rule on every directive. `Utils/wabbajack/models.py:28–48` excludes remapped inline, generated archives, transformed textures and archive metadata from its deterministic manifest-output check. Freeze applicable authored-format validation for each family, and always record the actual durable output digest for local reuse. Distinguish an author-specified required hash from an independent fixture digest and from the digest recorded after generation.

| Family | Proposed positive and failure oracles |
|---|---|
| `FromArchive`, `PatchedFromArchive` | A tiny admitted archive resolves one exact member (also a nested-member fixture) to `base\n`. A fixed patch with the approved source hashes yields `patched\n`; replace one source byte and assert refusal, no ready output. |
| `InlineFile`, `RemappedInlineFile` | `InlineFile` publishes exact fixture bytes. Remap a declared game, download and list path token to the reviewed path forms in a fixture INI; unrelated text stays byte-for-byte unchanged. Changing remap context invalidates reuse even with unchanged input bytes. |
| `PropertyFile`, `ArchiveMeta` | Each is reconstructed by the ordinary inline writer from `SourceDataID` in `Utils/wabbajack/reconstruct.py:1214–1239,1272–1289,1452`. Use two distinct payloads (`property\n`, `archive-meta\n`) and targets; preserve exact bytes. A missing or over-budget member yields no output. Treat the metadata as data, not launch or download authority. |
| `MergedPatch`, `CreateBSA` | Plan requires exact dependent outputs before either computation; reordered input schedule gives the same verified result. For `MergedPatch`, pin a synthetic two-source patch output; the pinned inspector accepts `OCTODELTA` version 1, not the BSDIFF format traced in Collections. For `CreateBSA`, independently inspect container version, member names/bytes and any manifest-required digest. Missing source and dependency cycles block before publication. |
| `TransformedTexture` | Use a tiny synthetic texture with fixed source and requested output properties; independently decode and check dimensions, format and mip count. Assert the durable digest matches the actual verified output, not necessarily a different encoder's output. Unavailable required transform or wrong output must not publish a silently untransformed input. |

Add these cross-effect witnesses to `list_stock_game`: exact local archive wrong hash leaves cache untouched; cut after Stock Game private output is durable but before profile publication and verify no base game changes; corrupt one retained output and resume rebuilds it rather than trusting a path; KeepLocal vs UseAuthor yields exactly the reviewed bytes; remove a list referenced by a deployed group and verify failed restore keeps group/profile/install ownership intact; reset restores authored order while retaining one unlisted mod and plugin.

`unknown_required_directive_never_materializes_a_partial_list`: an inert fixture with a known required inline output and an unknown required directive reports the exact unsupported discriminator before publication, leaves the active generation unchanged, and does not report completion. Run the supported subset's separate positive fixture with exact expected outputs; absence of an upstream executable must not alter the fixture's expected result.

For [desktop cache maintenance](../research/desktop-action-ledger.md#cleanup-and-operation-history), this packet owns list-store classification and cleanup. `list_cleanup_rechecks_install_references_and_recovery`: start with reviewed disposable work in a referenced list and a separate unreferenced installation eligible for retirement. Add a profile reference or protected recovery record after review; recheck under the operation lease, refuse affected cleanup and retain the installed output. Clear only proven disposable work, not the artifacts needed to retry or Restore. Define which optional work/backups can actually be discarded before freezing the fixture.
