# M2-D01: copy redeploy and recovery contract

**Status:** Draft handoff, not execution approval. Consumes [M1 copy recovery](m1-recovery.md), [its oracle](../research/recovery-oracle.md), and the accepted M2-P01 profile contract. Files and names below are proposed until the predecessor tree and native directory effects are known. Refine this packet independently of the subsequent link modes and multi-root work.

## Design

Apply a **delta to the current generation**, under the same exclusive installation lease, rather than calling Restore then Deploy as two separately committed operations. With the latter, an interrupted profile change leaves the user with neither deployed profile. The delta leaves the previous generation active until all new effects are durable; an uncommitted redeploy rolls back to it. Explicit Restore always returns to unmanaged originals, not to the preceding mod.

Retain the same root identity and one committing operation per installation. The operation initially accepts regular files and manager-created directories in the existing M1 `Data` root. Use the admitted physical spelling for a logical key that merely changes winning source spelling; do not rename an existing physical path for case alone. No link modes, cross-root transactions, file-to-directory conversions, or effect on launchers in this packet. Later handlers that need those transitions must have a separate checked contract; do not silently accept or permanently exclude them.

| Plan field or effect | Required contract |
|---|---|
| Base generation | Extend M1 `DeploymentPlan` with `expected_active: Option<DeploymentGenerationId>` (opaque core ID). `None` means no active generation, not “don't care.” Compare under the root lease along with exact profile revision, root identity, and source inputs. Exact already-claimed plan replay returns the recorded `OperationId` before checking current state. |
| Next-generation target union | Compare active owned targets with the next desired manifest. An unchanged, still-verified target has no public effect; an added or changed target has a checked publication; a dropped target gets its original back or a checked detachment if originally absent. Never use the next manifest alone as the removal list. If any old target is unknown, fail before starting new effects; a race after preflight goes through the existing conflict protocol. |
| Three records | Keep the unmanaged original for each active managed target, the operation's pre-step observation/recoverable bytes, and the actually displaced file when they differ. Share bytes by reference only when the data is durable under the qualified adapter contract and cannot be mutated through a public alias. Reverting a dropped target ends its ownership on successful finalize; reintroducing it in a later operation admits a fresh original, including any user edit made in between. |
| Parent directories | Add explicit ordered directory intents. Create only missing parents inside the verified root, ancestor before child, then publish files. Already-existing directories never become owned just by lookup. Carry created-directory ownership across redeploys; prune only on explicit Restore or rollback of the operation that created them, deepest first and only when still the same owned directory and empty. |
| Concurrent directory changes | If an outside writer claims a planned missing name after review, do not adopt it as owned. A replacement directory, unexpected child object that invalidates a managed path, or unavailable parent blocks the affected write and preserves evidence. If all managed files were restored and a still-owned directory contains only unmanaged entries, leave it and report the retained directory; release that directory's ownership on successful Restore. Never recursively delete a directory as cleanup. |
| Commit point | Persist the next generation, original-reference changes and final operation record in one metadata commit after durable effects. Startup after an unfinished redeploy restores the previous **committed** generation; startup after unfinished explicit Restore continues restoring unmanaged state. If rollback encounters an unknown target, keep the previous generation record but report a recovery conflict, not a healthy live view. A missing root allows only a validated same-root retry. |

The optional **profile snapshot** in M3-P03 and the required **recovery pre-image** are independent. A preference or automation request may suppress the former, never the latter.

## Subtasks for one orchestrator

1. **Shared contract and proof first (Sol review).** Freeze `DeploymentGenerationId`, intent representation and journal transition fields against the M1 artifact. Platform must prove identity-preserving no-clobber creation and safe empty-directory cleanup on the named ext4, Btrfs and native NTFS targets, including loss before ACK, nonempty/replaced names and namespace persistence. An expected pathname alone cannot establish directory ownership. Do not infer these guarantees from the regular-file proof. If no primitive meets them, park that effect and bring the scope/implementation choice back; no unsafe fallback.
2. **Pure planner and recovery decisions.** Own `crates/core/src/deployment.rs`, `crates/core/src/recovery.rs` and `crates/core/tests/redeploy_recovery.rs`. Use the previous-generation and next-manifest union, and refuse stale base generation even if profile revision is still current. Planner authors the following acceptance assertions; workers must not edit them. No SQL, native lookup, or UI logic in the planner.
3. **Persistence and native effects.** Storage owns `crates/storage/src/operation_journal.rs` and proposed `crates/storage/migrations/0003_deploy_generations.sql`; platform owns the new directory-effect implementation under `crates/platform/src/physical_copy.rs` and its native checks. Disjoint writes are allowed only after step 1 freezes the interface. Extend the existing journal and adapter; do not add a second engine or rewrite old operation history. A migration with in-flight M1 work must preserve its recovery references.
4. **Client reporting and integrated proof.** Desktop and CLI consume the same authoritative active, pending, and conflict result; do not implement recovery in a client. Freeze exact client paths after M1-U01. Compare selected and deployed profile IDs even when names match. Use the M1 process/power-cut setup to qualify the new transaction and directory effects; model-only results do not qualify an OS. Record unresolved directory evidence before releasing D02 or any feature depending on it.

## Frozen-fixture candidates

Use the M1 golden fixture. Generation `g1` owns `Data/textures/winner.dds = b\n` over original `base\n`, plus `Data/textures/a-only.dds = only-a\n` over absence. `Data/untouched.txt = keep\n` is never managed. Generation `g2` supplies `textures/winner.dds = a\n`, drops `a-only.dds`, and adds `textures/new/sub/item.dds = new\n` under two missing directories. No fixture binary or live install is required.

| Future test | Required assertion |
|---|---|
| `base_generation_change_rejects_old_plan` | Preview from `g1`; commit another valid plan first. The old unclaimed plan returns `StalePlan`, with zero public effects even if its profile revision still matches. Replay of the committed plan returns its existing operation without effects. |
| `interrupted_delta_restores_previous_generation` | Cut after detaching `a-only`, publishing the new winner, and creating the nested file, before final commit. Recovery restores `b\n` and `only-a\n`, removes only the owned new file and its empty new directories, leaves `g1` active, and still retains `base\n`. The second recovery makes no mutations. |
| `committed_delta_restore_uses_unmanaged_original` | Commit `g2`, restart with another profile selected, then Restore by recorded installation identity: winner becomes `base\n`, `a-only` and `item` are absent, `keep\n` survives, and no generation is active. Repeat Restore is a no-op. |
| `dropped_target_reintroduced_backs_up_new_original` | After `g2` dropped `a-only`, create `a-only.dds = user\n`. A newly reviewed generation publishes `only-a\n` there. Restore returns `user\n`, not absence; no stale `g1` ownership authorizes removal. |
| `external_edit_blocks_redeploy_rollback_without_losing_original` | Before `g2` finalizes, replace its `winner.dds` with an unrelated `edit\n` file at the same name. Recovery retains `edit\n`, the step pre-image `b\n`, and the original `base\n`; reports `RecoveryConflict` with `g1` as the last committed generation, not a healthy deployed view; and refuses another apply on the same root. |
| `directory_retains_unmanaged_child_and_never_adopts_substitute` | In one case add `new/keep.txt = user\n` after `g2`; Restore removes `sub/item.dds` and empty `sub`, retains `new/keep.txt` and reports retained `new`. In a separate case substitute `sub` before cleanup: no deletion of the substitute or its contents, report conflict with ownership evidence kept. |
| `rollback_does_not_depend_on_profile_snapshots` | With no profile snapshot support installed in the fixture, inject failure after replacement and before finalize. The mandatory recovery evidence still returns the exact previous generation. M3-P03 exercises both values of the actual snapshot preference without changing those recovery results. |

Proposed logical check: `cargo test -p marduk-core --test redeploy_recovery`. Planner records the initial behavioral failure and then checks the same assertions after implementation, including operation status and reference retention, not just bytes. Freeze the native and integrated check commands after M1 proof infrastructure exists. Record supported metadata, generation IDs, backup references, exact cut and observed outcome per run. A clean deploy/restore cycle cannot satisfy the new failure witnesses.
