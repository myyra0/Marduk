# Improvement backlog

Optional improvements that are not scheduled in the parity rewrite because they need separate research, new scope, or significant work. This is not a list of everything we could improve. Put small, safe improvements directly in the owning [execution packet](superpowers/plans/2026-11-20-full-parity.md) with an acceptance check. Remove an idea from this backlog once the packet takes ownership. Neither a missing parity capability nor a correctness fix belongs here.

| Idea | Area | Why | Effort (S/M/L) |
|------|------|-----|----------------|
| Evaluate a virtual-file-system deploy method (USVFS-style on Windows, bind/overlay on Linux) | Deploy methods / `DEP-*`, `G-PRIVATE-WIN`, `G-LICENSE` | A private view removes the whole displaced-bytes/retention class instead of reconciling it: the game reads an overlay and the install is never written, which is why the peer implementation is battle-tested there. It is not a cross-platform M1 answer — USVFS is process injection and Windows-only, Linux needs bind/overlay with its own launch and Proton/tool routing — so it stays a deploy-method adapter behind the existing seam. Explore when a real canonical-path requirement, unacceptable copy write amplification, or a Windows launch-compatibility failure appears, and only with licence/notice review, write-isolation witnesses and a safe-failure route | L |
| Compare the three Linux private-view routes (overlayfs, bind mounts in a launch namespace, FUSE) | Deploy methods / `G-PRIVATE-WIN` | Linux has no injection runtime, so the route decides everything: user namespaces are often disabled, bind mounts need a namespace we control at launch, and FUSE costs per-file overhead on large mod trees. A Steam-launched title leaves our namespace entirely, so launch routing is part of the choice. Measure per route before claiming any | L |
| Benchmark independent copy-on-write clones and incremental shadow-tree rebuild | Deployment performance / `DEP-01`, `DEP-04` | May cut write amplification without making a game edit mutate the mod library. Adopt only with comparative evidence | M–L |
| Estimate required space before deploy when storage and backup costs span multiple volumes or private-view layers | Deploy planning / `DEP-02`, `DEP-03` | Useful beyond the in-scope target and backup summary, but accurate forecasts need per-method measurement and accounting | M–L |
| Optionally corroborate linked Workshop item metadata against Steam | Source provenance / `SRC-05` | Could detect removed or wrong-game items; qualify access, preserve offline linking, and never label Steam metadata as verified install or archive bytes | S–M |
