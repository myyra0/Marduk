## Shared fixtures and known evidence gaps

- **BepInEx:** `plugin_package_identity_and_explicit_route`; enumerate each handler's own package domain and exact executable. `Games/BepInEx/graveyard_keeper_2.py:16–28` and `Games/BepInEx/inscryption.py:16–36` both declare Steam `1092790` but have different executable identities. The pinned cross-check must reject a false positive; do not infer a replacement store ID or remove either candidate without authoritative evidence.
- **Bethesda:** parameterize ordinary loose data/profile INI/order on each title's named paths and eligible plugin/archive types; use the per-row differences and the M3-B01 and M4-Y04 tool cases. A missing managed profile/target does not become a sibling title match.
- **RE invalidation:** `re_hybrid_second_effect_failure` plus positive and negative archive witnesses. `Games/RE_Engine_Invalidation/re_engine_invalidation_base.py:48–93` gives the build-dependent remaps; prove both modern and legacy branches for the three handlers with override constants. Fixture refuses a stale branch observation instead of applying the previous route. **RE loose:** `re_loose_roles_and_restore`; require a physical-mutation witness only if independently traced for that route.
- **Open:** exact edition/store/build and launcher availability, platform-only data locations, and installed registries still need their own evidence. These rows cover the static candidate denominator and assign distinguishing fixture work; they are not a frozen exhaustive case matrix for every override or a runtime test result. The [repository data snapshot](first-run-catalog.md#52-data-only-game-definitions) has a separate denominator.
