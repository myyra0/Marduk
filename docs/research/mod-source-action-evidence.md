## Manual linking and bulk identification

1. **Resolve and review:** `gui_qt/app.py:6030–6040` supplies game, profile, staging, mod and API. `gui_qt/dialogs/source_link.py:179–207,233–313` keeps Resolve read-only, offers versions and uses a sequence for version re-verification. The Resolve result itself carries no request sequence; a game/profile check is not proof the current URL/choice is the one resolved. Verification “none” prompts Link anyway only with a nonempty local version. A separately detected identity conflict prompts Replace on Apply (`gui_qt/dialogs/source_link.py:327–366`). A canceled review does not stamp metadata.
2. **Apply and follow-up:** `Utils/mods/source_link.py:175–205,208–274` rejects symlink mod/metadata paths, re-verifies and rechecks a metadata token under a lock, then stamps provider metadata and the marker in separate helper calls. Follow-up runs outside the lock and a failed dependency check does not undo the stamp. `gui_qt/dialogs/source_link.py:209–230,327–332` blocks dismissal during the write and suppresses a stale result, not a write already begun. `gui_qt/app.py:6042–6094` offers only missing repository dependencies, not reinstall of the linked root; the follow-up callback itself does not carry the original profile into dispatch. `source_link_rechecks_exact_review_and_never_installs_the_existing_root` (M3-S02/S03/S04): superseded Resolve, mismatch vs no evidence, stale metadata or account, marker failure after source stamp, and scope change before dependency approval. Distinguish partial metadata, metadata-only success and a separately approved dependency plan.

**Bulk Identify Installed Mods is a writing scan, not the manual linker.** `gui_qt/app.py:6239–6304` starts the worker without passing a cancel hook and checks game/profile on result delivery, after work may have been performed. `Utils/mods/source_link.py:290–343,345–435` scans configured repository communities, then handles BG3 PAK metadata with configured access. It reports existing Workshop IDs in the fallback branch and leaves Nexus for manual linking. It never runs dependency follow-up. `Thunderstore/thunderstore_identify.py:75–113,148–204,207–286` scans root or one-level manifests, skips symlinked mod folders, and does not overwrite an existing package stamp. Thunderstore can accept a namespace suggested by a folder name or select by version/popularity when ambiguous; Hexium requires a unique catalog match for stamping. A `matched` row does not itself prove newly written metadata. `bulk_identify_reports_existing_new_ambiguous_and_partial` (M3-S03/S04): same package name/version in two namespaces, plausible fake folder name, dual configured communities and stale profile. Ambiguity needs review, not automatic authority to replace a provider binding; interruption reports what actually committed without installing anything.
