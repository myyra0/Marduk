# Desktop settings and conditional actions

Source-only evidence from the [pinned baseline](../inventory.md); paths are relative to `src/`. A control can change a draft, save a preference, update the running UI, or authorize a separate operation. Preserve the observed outcomes with the project's stronger scope and recovery rules. Proposed witnesses are not frozen.

## Restore, launch setup and account transitions

- **Restore on Close and runtime capture policy (M2-D01/L01/M3-X03):** `gui_qt/settings/view.py:1414–1434,1638–1661,1728–1755` saves Restore on Close and separate global runtime-capture patterns immediately. `Utils/deployment/shared.py:938–977,1938–1983,2018–2031` matches file basenames and folder components case-insensitively at any depth. This can skip moving runtime-created content; it does not exempt verified managed files from Restore. `gui_qt/app.py:14852–14957` gates some active operations, pauses Wabbajack for shutdown, then checks the preference and restores eligible configured/active deployments, not only the selected game. Failed restores are logged while it proceeds toward closure; a settings Restart runs the same path. `close_restore_keeps_pending_recovery_and_never_releases_live_views`: eligible/ineligible game, active managed process, Wabbajack pause, failure on the second game, agreed opt-out, broad capture pattern and changed game path. Do not substitute logging or app exit for authoritative Restore. Preserve restoration of unmanaged originals independently of optional capture suppression.
- **Executable settings and Proton action builders (M2-L01/M4-Y02/Y03):** `gui_qt/launchers/exe_settings.py:330–417` loads options by executable basename, gates framework override controls, and writes args, runtime/prefix mode, capture, Deploy-on-Run and applicable Java or Wine options on Save. Remove deletes a custom list entry or hides an auto-detected one, not executable bytes. `gui_qt/app.py:15630–15745,15824–15903` distinguishes game-prefix utilities, Health inspection, existing-prefix component UI, and serialized installer operations. LAV is keyed by declared deps. The game-EXE picker captures a game object but no prefix revision; some installer callbacks look up `self._gs.game` inside a worker although the outer lease uses the earlier game object. `runtime_settings_and_installer_lease_bind_the_exact_executable_and_prefix`: same basename from two origins, missing runner, framework constraints, switched target after picker/lease, stale result and post-install runtime verification. User-picked utility execution does not imply permission for a different prefix. Keep [per-executable prefix setup](desktop-action-ledger.md#conditional-prefix-tools) a separate effect.
- **Explicit command generation vs archive Deploy (M4-Y01/M2-L01):** `gui_qt/app.py:14592–14619,14812–14824` prompts on explicit Mewgenics Deploy when the handler offers the command alternative. Cancel does neither; selecting Steam generates a profile-scoped modpaths file and opens a command display, not a game process. Selection of repack calls Deploy; silent auto-deploy reaches repack without that prompt. `mewgenics_command_generation_is_not_repack_or_launch`: profile changed while prompt open, no recognized inputs, command clipboard vs actual launch, and a silent operation that would modify `resources.gpak`. Keep the [standalone archive wizard](title-patch-evidence.md#merge-unpack-and-repair), managed repack and command generation separate. Auto-apply cannot change a reviewed destination/method.
- **Connections Load/Test & Save/Clear (M3-S02/M4-S04/A03):** `gui_qt/settings/connections.py:13–32,143–199,202–292,294–332` creates independent mod.io and LoversLab jobs. Editing invalidates pending work; Test & Save verifies before persistence, under a generation check before the write. Clear has a separate completion; closing invalidates result delivery and signals stop, but not a storage operation already committed. Nexus status reflects cached account/tier/rate limits. `gui_qt/app.py:8922–8995,8997–9061` starts browser sign-in or prepares a clipboard link for the active attempt, supports code submission only with a live client, and invalidates auth state before clearing stored credentials. The paste reply checks current client liveness but doesn't capture which attempt opened the prompt. `credential_controls_reject_late_test_or_code_and_report_clear_result`: superseded form or auth attempt, invalid verification, closed overlay, clear failure, network challenge and unavailable keyring. No credential fallback or live proof is approved; never expose secrets in logs or data fixtures.

## Frame generation and overlay launch prerequisites

- **Editor draft, live preview and install differ (M2-L01/M4-Y02/Y03):** `gui_qt/app.py:14310–14384,14401–14436` saves accepted settings and tries to regenerate a launcher handoff; failure of the second effect does not undo the first. `gui_qt/launchers/lsfg.py:637–690,693–750,869–904` runs setup, probe, update discovery and rollback as separate actions. Existing generated config gets debounced edits for the current live backend; on Cancel the view attempts to write the original values back, without restoring the original bytes or undoing an installation. Changing backend is not a live backend switch. `framegen_preview_cancel_does_not_undo_install_or_overwrite_newer_settings`: backend change, cancellation during independently accepted setup, already-running profile, missed/failed config replay and external edit. Bind the live preview to the exact owned process/config; distinguish editing, installation, handoff generation and what the running process actually accepted.
- **MAKO and LSFG-VK setup use different ownership (M4-Y03/A03, G-EXT and G-LICENSE):** `Utils/executables/mako.py:13–28,89–128,147–181,244–287` pins MAKO Renderer 5.0.0 and a SHA-256 for Linux x86-64, validates archived files/version before selecting a new owned installation and permits switching to a validated previous one. The setup probe distinguishes optional MangoHud architectures, DLL-based and built-in frame-generation models and config validation—not GPU execution. `Utils/executables/lsfg.py:15–23,26–90,118–180` discovers a local/host Vulkan layer or selects the highest stable version from the upstream build page, then merges files into user-local shared paths. The temporary backups recover caught failures, not abrupt process loss. The external Lossless Scaling branch/DLL and runtime visibility are separate prerequisites. `renderer_install_and_rollback_bind_exact_artifact_and_scope`: wrong architecture/version, checksum mismatch, user-owned collision, interrupted shared install, missing previous artifact and a later upstream version newer than the supported selection. Do not assume rights to ship the renderer, DLL or installer payload.
- **Launch-time configuration and runtime visibility (M2-L01/M4-Y02/Y03/A03):** `Utils/executables/launch.py:1036–1137` selects one config backend, falls back to launch-time environment if LSFG-VK config writing fails, and composes MangoHud options with existing launch environment. `Utils/executables/mako.py:291–305,405–445` can wrap host launches (including through the sandbox-to-host bridge) and refuses a game running inside a launcher Flatpak without a different runtime extension path. `renderer_visibility_is_not_host_install_success`: optional layer absent, existing environment, two competing layers, host-visible/in-sandbox-invisible payload, denied host bridge, and fallback with equivalent versus incomplete effective settings. No invented Windows toggle or product-supported runtime claim follows from these Linux environment paths.
