# Multi-root title deployment evidence

Three built-in handlers from the [pinned source](../inventory.md). Paths are relative to `src/`. A resolved destination, a successful generator or router, and a running game reading the intended data are separate claims. All witnesses below are draft; none establishes installed Windows or Linux behavior.

## Prey base game, Mooncrash and executable roots

- **Admission and edition routing:** `Games/Prey/prey.py:25–55,59–113,116–162` marks a structured/root layout. A staged root `ChairManager.exe` moves its framework together into `Chairloader/`, retaining `meta.ini` outside. For mods, follow a single non-protected wrapper toward `ModInfo.xml`; valid `modName` selects `Mods/<name>/`, whereas unreadable/invalid XML leaves files where staged. A loose ZIP-readable `.pak` is moved to `Whiplash/GameSDK/Precache` only if it contains a Mooncrash-exclusive path and no base-exclusive path. Mixed, shared-only and unreadable files are not moved by that hook. The two compressed lookup tables are declared in `Games/Prey/meson.build:1–8` and attributed in source to Steam build `5297220`. That is pinned data provenance, not independent proof for a later release/store or distribution clearance.
- **Deployment and store divergence:** `Games/Prey/prey.py:15–23,151–157,164–206` uses ordered loose-only rules: named Engine/Localization assets, `game.cfg` and `Levels`, filename signs of Mooncrash, default base precache, executable-relative add-ons/DLLs/tools/presets, and prefix-local `Shaders` in Saved Games. Structured files are not rerouted by the loose rules. `_exe_dir` prefers present GOG then Epic directories and defaults to Steam; the generic executable resolver (`Utils/executables/launch.py:1186–1226`) uses a different selection boundary: Steam is first in the declared list, then alternatives, with a basename fallback. Both Steam and GOG files in one root can therefore select different route and launch targets. A filename is not proof of store ownership. `Games/Custom/custom_game.py:845–893` separately handles physical custom paths and root publication; `Utils/deployment/custom_rules.py:776–782` drops prefix-required rules without a prefix, not a successful shader install.
- **Draft checks (M4-Y01/Y02, M3-X03):** Extend `prey_variant_layout_and_store_roots` with simultaneous Steam/GOG/Epic files, controlled user selection for ambiguity, archive content vs filename, initially structured assets, malformed XML, source/role collision and missing prefix. Resolve one approved executable identity for both launch and neighboring resources. Keep native Windows Saved Games location and Wine mapping separate. Fail/recover when only the second reviewed root is writable; never claim that dropping one route is parity.

## Cyberpunk archive order, REDmod and external launchers

- **Archive publication is not REDmod (M4-Y01/Y03):** `Games/Cyberpunk 2077/cyberpunk_2077.py:154–170,342–354,363–419` remaps `archive/pc/patch/` to `archive/pc/mod/`, routes flat archives and `.xl` companions and builds optional `modlist.txt` for flat resolved `.archive` files only, highest priority first. Overwrite wins; raw/custom separator outputs are excluded from that list. `Games/Cyberpunk 2077/cyberpunk_2077.py:421–518` writes the list in CRLF, preserves an existing custom order (physical ownership checked by comparison with saved bytes, private path guarded), and turns optional ordering errors into warnings. The private build runs REDmod separately after the order attempt.
- **Required generator and readiness (M4-Y01/Y03/X01/X02):** `Games/Cyberpunk 2077/cyberpunk_2077.py:41–64,568–693` triggers on existing or planned `mods/<name>/info.json` and nonempty/invalid cache or planned cache contents. Read-only preflight checks the DLC's `tools/redmod/bin/redMod.exe` from the game or approved plan, game Proton runtime and prefix compatibility. The private route refuses cache symlinks, rebuilds the local `r6/cache/modded` tree and runs that executable against the exact view using game-prefix path translation. A nonzero result is fatal; zero does not validate fresh cache content. Contrast empty roots, last mod removed with stale cache, inactive Root Folder provider, missing DLC, prefix mismatch, physical vs private roots and unsafe cache. Native Windows needs a separately proven runtime and no real game required for the synthetic differential checks.
- **Managed arguments vs external config (M2-L01/M4-Y02/A03):** `Games/Cyberpunk 2077/cyberpunk_2077.py:199–205,695–782` adds `-modded` to manager launch arguments; `post_deploy` independently attempts external launcher argument changes even after archive-only deployment. Steam uses the effective app ID, respects a running Steam refusal and warns/manual fallback; Heroic resolves app names and checks/writes its arguments. The warning toast is suppressed for a pending managed launch, not the attempted configuration effect. `redmod_external_argument_review_is_separate_from_deploy`: accept managed launch without authorizing external settings; verify exact store/account/app configuration if separately approved, no duplicate token, no stale writer, and explicit unsupported/unknown launcher state. No claim that the Steam/Heroic branches prove GOG Galaxy, Epic or native Windows dispatch.

## Red Dead Redemption 2 LML and root loaders

- **One package can contain two target roles (M4-Y01):** `Utils/games/rdr2_routing.py:15–48,50–96` filters packaged tool/example payloads via its caller, gives explicit `lml`, `install.xml`, `stream` and `replace` trees precedence, and uses loader/ASI parent anchoring plus separate loose rules for the root route. `Games/Red Dead Redemption 2/red_dead_redemption_2.py:118–174,181–220` resolves per-mod paths, reconciles explicit routing overrides, and refuses multiple eligible ASI variants before deployment unless unused paths were excluded or a raw route was explicitly selected. Match structured LML, root bootstrap and companions, protected subtrees and identical ASI names in two variant folders; directory resemblance does not authorize both copies.
- **Generated order and original state (M4-Y01/M3-X03):** `Games/Red Dead Redemption 2/red_dead_redemption_2.py:269–301,400–449` writes optional `lml/mods.xml` in physical or private mode and separately captures runtime files outside `lml`. `Utils/games/rdr2_load_order.py:14–84,87–145` only ranks actual routed `install.xml` folders, puts highest-priority last, retains unrelated XML entries and refuses multiple case-equivalent `mods.xml` files. The physical route requires `lml_Core`, records target and original/generated digests before writing, and saves independently changed generated XML before removing it on Restore. `lml_order_generation_preserves_unmanaged_entries_and_runtime_edits`: include unowned XML and a duplicate-case decoy, already-restoring record, missing backup and one changed output. Preserve both the original and independently edited result with review; loader visibility under a real launched game is a separate witness.
