## Base behavior found outside or beyond the headless method names

- **Data-only handler catalog.** A built-in user workflow acquires and selects repository-backed JSON definitions; it is not a manager plugin host. Store publisher/source and definition revision independently from title ID. Sync into a cache, validate before selection, and keep an installed or deployed instance pinned to its approved definition until safe reconfiguration. One [observed snapshot](first-run-catalog.md) contains 52 definitions, not 52 verified layouts or runtimes.
- **Steam Workshop identity.** `Utils/mods/source_link_stores.py:600` sees a Workshop page as `(store app ID, item ID)`, not a generic URL. `Utils/mods/install.py:1614` rejects matching sidecar metadata for the wrong game; the mod context menu can open the item. `Utils/games/workshop.py` declares 16 app IDs, an alias for The Witcher 3 and two routing exclusions. The tracked `Utils/wizards/workshop.py` covers ID parsing, metadata and cache migration. The [catalog snapshot](first-run-catalog.md#seven-optional-store-entries) does have a separate, optional downloader. Do not infer that downloader is present in the base package or discard the independent base linking/provenance behavior.
- **Plugin content mutation.** Changing ESL status is not the same as turning a row on or setting its order. Expose it only for supported, validated files and make it recoverable without changing profile or source bytes that weren't approved. Preserve OpenMW groundcover routing independently.
- **Explicit support sharing.** In addition to local logs, the application can upload a redacted session log and return a public link. Retain the reviewed outcome independently from the old paste host and retention policy. The proposed local export preview is not a substitute for the existing upload action. Provider selection and any live upload stay behind G-EXT and explicit user consent.

## Packaging and public link entry points

- The tracked AppImage and Flatpak desktop entries pass one URL argument. Native Linux handlers separately register `nxm` (`Nexus/nxm_handler.py`), `ror2mm` and `gale` (`Thunderstore/*_handler.py`), `modl` (`Utils/downloads/modl.py`), and `wabbajack` (`Utils/wabbajack/protocol.py`). The protocol outcome is typed dispatch with validated provider/game/object ID, not reusing argument parsing or old desktop registration. The manager-plugin-owned scheme is excluded. Record a cold launch and a running-app handoff per applicable scheme; malformed input must not trigger work.
- `meson.build` plus `src/meson.build` install desktop/CLI and native runtime files. Nix, AppImage and Flatpak differ in how commands, native helpers, browser launch and visibility of host files are owned. This is package-source evidence only. Test for missing helper, absent host access, sandbox file chooser paths and clear mode/ownership disclosures.

### Collection install and removal

- `gui_qt/app.py:6686–6722,6774–6785` distinguishes standalone removal through profile removal from appended removal with a delete/retain preview, a retained host profile and shared downloads. The global installed card's appended submenu only offers toggle/remove (`gui_qt/collections/installed.py:78–105`); the separate active-profile browser **does** wire appended “View” (`gui_qt/collections/browser.py:400–450`).
- `gui_qt/app.py:6654–6684,6903–6925` opens detail with the selected installation and revalidates it before install. `gui_qt/collections/detail.py:730–821,880–919,1050–1064` re-reads an appended record by slug and install ID, remembers its optional skips, and offers Resume or Update outside explicit Append/Group/Download-only mode. A different viewed revision can be older or newer; “update” is not “always install latest.”
- `gui_qt/app.py:7265–7310,7327–7386,7402–7424,7446–7472,8171–8197` dispatches a bound appended resume in append mode, routes interrupted updates through the diff, and uses the original host profile for revision replacement. Update refuses inactive/locked/group or deployed-containing-group targets. `Utils/collections/install.py:2517–2607` computes readiness before retirement and writes the appended ownership record separately from standalone profile manifest/state. This proves source reachability, not restart durability or packaged runtime. [M4-S01](../contracts/m4-collections-install.md) retains these desktop outcomes without assuming the old headless endpoints accepted them.

### Collection authoring and remote visibility

- `gui_qt/collections/create.py:590–643,1082–1121,1144–1222` saves local drafts and separately confirms a provider upload and draft registration. The reference explicitly warns that a deleted target may instead create a new draft. Marduk proposes retaining that outcome through a separate Create review on target loss so the reviewed update cannot mutate another resource.
- `src/Nexus/nexus_api.py:3975–3999` sends v3 create/revision requests. The revision path may edit the parent name first, so registration failure does not by itself prove there was no metadata change. The separately documented GraphQL draft upsert is not evidence that the pinned v3 path replaced existing drafts. M4-S02 must expose the rename effect and qualify the exact create/update semantics before freezing the upload route.
- `gui_qt/collections/mine.py:425–475,588–717` installs the author's draft for testing when there is no published revision, edits metadata and changelog, confirms listed/unlisted publication and adult flag, and changes an already published collection's listing separately. A successful upload alone is not publication. These desktop outcomes are [M4-S02](../contracts/m4-collections-authoring.md); the pinned headless registry does not establish equivalent remote-publish commands.

### Provider routes and updates

- `gui_qt/app.py:5556–5604` handles an exact pending list acquisition before ordinary NXM forwarding and game-instance selection. `gui_qt/nexus/nxm_routing.py:19–37,70–121` queues and forwards a validated link with return-loop handling. Preserve the handoff, not the Linux-only desktop command format, and never copy secret-bearing URL logging.
- `gui_qt/app.py:10306–10336` splits a mixed Quick Update selection into a Nexus flow and a separate repository queue, binding the latter to the originating game/profile. Test the repository work even if Nexus authentication fails.
