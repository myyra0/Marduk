# Game and tool parity witnesses

**Status:** Pinned-source behavior and proposed synthetic fixtures. No reference selftests, games, tools, or downloads were run. Paths in the evidence column are relative to `src/` at the [baseline](../inventory.md). The [tool crosswalk](tool-crosswalk.md) owns the static key and handler counts.

## Distinct game behaviors

Do not create one identical fixture per title or treat one game per engine as sufficient. Share a fixture only if input layout, effect roots, runtime routing and restore behavior match. Preserve a title-specific assertion where one differs. All executables, DLLs and asset bytes below are synthetic markers; the packaged/live route has separate evidence.

## Conditional title and tool routes

- **OpenMW launch and config have to agree (M4-Y01/Y02/M2-L01):** `Games/Morrowind/openmw.py:343–389,391–416,426–501,507–526` offers a skip-launcher choice only for the base handler; an instance always requests the engine and supplies its own config directory. Linux selection prefers Flatpak unless AppImage is preferred, then tries ordinary native detection; the skip path requests the AppImage bundle's separate engine. A selected AppImage may require host dispatch and can use a different display backend from the UI label. Config location is resolved separately and can still follow detection even if the selected launch mechanism falls back. `openmw_engine_and_config_are_selected_as_one_route`: launcher-only AppImage, missing companion, denied host dispatch, native fallthrough, explicit config override, two instances, and alternate backend. A missing engine must not launch against another config, and reopening the launcher must not silently lose committed managed ordering.
- **No Man's Sky request vs running settings (M4-Y01/M2-L01):** `Games/No Man's Sky/no_mans_sky.py:334–363,369–436,472–501` reads an unconsumed Disable all request before persisted and live settings. Saving the control requests the next generation, not undeployment or a live write. An explicit Root Folder owner suppresses generation; a successful generated write captures settings before clearing the matching pending boolean. `nms_disable_request_is_consumed_only_by_its_commit`: toggle with and without Deploy-on-Run, Root Folder owner, failed generation, preference changed twice while work runs, VR flags, external live edits and later Restore. Bind consumption to a request revision, not just boolean equality. Both direct and provider overlays route title controls through the same reader/writer (`gui_qt/app.py:14387–14454`, `gui_qt/launchers/provider_settings.py:123–139,339–370`, `Utils/executables/launch.py:725–744`).
- **BG3 runtime and Collection order (M4-Y01/Y02/S01 and M3-B01):** `Games/Baldur's Gate 3/baldurs_gate_3.py:78–86,392–473,557–579,627–656,703–726,827–905` separates user PAKs, loose/replacer `Data`, DLL-only Collection extender `bin`, selected patch mode and XML ordering. Legacy metadata may fall back from exact file ID to names; avoid silently restamping an ambiguous match. Actual user PAKs are flattened at the top level, and an authored PAK order can interleave entries from different mods. Certain install types are not order entries. `bg3_collection_routes_and_recovery_are_runtime_scoped`: both runtime binaries present, missing user root, same label with different file ID, two PAKs in one staged mod interleaved with another mod, override PAK and explicit non-order output. Restore rejects mismatched runtime target and preserves modified live XML separately from the original (`Games/Baldur's Gate 3/baldurs_gate_3.py:168–230,935–986`). Native Windows user-data discovery needs separate proof; the combined Windows/Proton label in the reference still requires a prefix.
- **BG3 import and launcher warnings are not deployment results (M4-Y01/M2-L01):** `wizards_qt/bg3_import_view.py:86–103,129–175`, `Utils/bg3/importer.py:125–146,172–286,289–309,340–343` parse a selected order, match staged PAK UUIDs, report missing entries and preserve extra installed mods; Apply writes the reviewed profile order, not `modsettings.lsx` or a provider install. It does not check the modlist revision it previewed. Physical Deploy separately tries to update four warning flags in an existing launcher preferences JSON, not telemetry; Restore does not undo those flags (`Games/Baldur's Gate 3/baldurs_gate_3.py:234–261,890–905,935–986`). `bg3_import_is_local_and_launcher_preferences_are_explicit`: stale plan, missing UUID with same name, cancellation, no implicit Deploy, preferences file missing/bad or externally edited, and separate request/result for any recoverable launcher-preference change. Retain the supported managed launch outcome without hiding that extra write.
- **Bannerlord framework choice (M4-Y02/Y04/M2-L01):** `Games/Mount & Blade II Bannerlord/mount_and_blade_2_bannerlord.py:60–115,124–128,184–235` separates ordinary `Modules` content, the game's native-named Windows executable and separate BLSE vanilla/extended Windows launchers. `bannerlord_framework_does_not_replace_game_identity`: one of the two BLSE targets present, opposite target requested, inactive staged target, then verified deployed/private target. Use the existing extender witness for top-folder preservation. Do not silently choose the other BLSE entry or interpret the executable basename as an OS capability.

### Archive-supplied routing instructions

**M3-I02/C01/X03 and M4-Y01/X01/X02:** The data-only Vortex instruction format is mod input, not old manager compatibility or permission to execute third-party code. `Utils/deployment/vortex.py:22–47,59–94,107–223,231–286` accepts `copy` and `setmodtype`, rejects unsafe relative paths, gives root metadata priority over nested metadata, and preserves source identity after installer transforms. Missing, malformed, ambiguous or unknown data can fall back to ordinary routing in the pinned implementation; a different plan requires new review, not a silent downgrade. `Utils/filegraph/adapter.py:1081–1126` skips metadata as payload and yields to whole-mod Root, per-file Root, explicit/raw separator placement and recognized custom claims. `Utils/mods/install.py:449–463,1899–1902,1949–1950` preserves original-to-staged mapping through extraction/normalization.

| Mod-type family | Distinguishing effect |
|---|---|
| Shared `dinput`/`enb` and declarative custom types | An explicit copy without a mod type uses the handler's default domain; a recognized type can bind all remaining payload to its typed role. A duplicate/escaped original source never multiplies or redirects placements. `Utils/deployment/vortex.py:35–47,170–223`. |
| No Man's Sky and Stardew Valley | No Man's Sky has separate `Binaries` and older `GAMEDATA/PCBANKS/MODS` instructions. Stardew's SMAPI and root types do not share the configuration mod's `Mods` target. `Games/No Man's Sky/no_mans_sky.py:299–304`, `Games/Stardew Valley/Stardew Valley.py:45–50`. |
| Sims 4 and Witcher 3 | Sims mixed user content is a prefix role; Witcher 3 distinguishes `DLC`, install-root types and the prefix Documents menu route. Neither may substitute the install folder when user data is missing. `Games/The Sims/the_sims_4.py:14–20`, `Games/The Witcher 3/witcher_3.py:125–135`. |

`instruction_routes_share_the_reviewed_generation_and_restore`: positive typed fixture plus malformed or unknown type, competing custom/Root rules, renamed staged file, private game/data vs physical prefix, and failure after the first write. `Utils/deployment/pipeline.py:393–419,1101–1111` preflights recorded paths/restore separately, then applies routed entries after the physical handler; `Utils/vfs/overlay.py:1721–1733` uses disposable game/data layers while `Utils/deployment/vortex_deploy.py:14–76,79–129` can still journal a physical prefix effect. The same reviewed destinations must drive preview and writes; an interrupted hybrid must not publish a completed view or lose the prior generation.

The [handler matrix](game-handler-ledger.md) assigns per-ID checks for compiled candidates; the [catalog matrix](first-run-catalog.md#effective-route-checks) assigns checks for data-only routes. These are source candidates and fixture requirements, not installed registry reachability, validated art/tool artifacts or native compatibility.
