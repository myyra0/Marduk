**Evidence level:** Pinned-source trace, not a claim that all formats work in every package. Source paths in this file are relative to `src/` at the [inventory baseline](../inventory.md).

## Planning decisions

- Prefer in-process Rust readers that yield entry inventory and bounded streams. The archive reader doesn't choose where to write; the staging module consumes a checked path plus a verified stream. Treat extractions and native readers as untrusted input adapters, not desktop shell commands.
- A native helper for a format the Rust options can't cover is an explicit distribution and isolation decision. Require deterministic listing, verified entry-to-output correspondence, controlled temporary roots, no output outside that root, bounded resource use and clean cancellation on both OSes before making it available. Do not ship a helper just because the reference happened to use it.
- ZIP variants (including ZIP64 and non-default compression), RAR versions, 7z and TAR compression/special entry cases need positive and negative fixtures before an individual format is announced. List separately what was recognized, listed, extracted and used to complete a mod install. Game-container formats such as BSA/BA2 have their own `M3-B01` reader/writer and fixture policy.
- The first implementation brief still needs to freeze the exact ZIP reader crate/version and features, concrete archive/stage interfaces, and platform proof for real bounded file creation. Closing the format audit requires inspecting the packaging dependency recipes and reproducing admitted fixtures in isolation, not running the reference installer on a user's game.
