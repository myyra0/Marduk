# Provider upstream evidence review

**Status:** Read-only review, 2026-11-20. Public documentation, provider policies and upstream source were inspected. No accounts, provider API calls requiring credentials, mod/list downloads, published writes, binaries or runtime tests were used. The selected web search returned no results; direct official sources, Context7 and GitHub MCP supplied the evidence below. This does not close [G-EXT](../architecture.md#decision-and-proof-register).

## Nexus Mods — M3-S02

- The [public REST v1 specification](https://app.swaggerhub.com/apis-docs/NexusMods/nexus-mods_public_api_params_in_form_data/1.0) documents download links by game/mod/file. Its non-Premium route needs the website-issued NXM key and expiry for that file/user; invalid grant, entitlement refusal, missing file and expiry are different outcomes. The website's [resumable download](https://help.nexusmods.com/article/170-resumable-downloads) is a browser flow, not evidence an application can reuse its partial or resume on the CDN.
- The [API AUP](https://help.nexusmods.com/article/114-api-acceptable-use-policy) covers application registration, disclosed application identity, personal-key limits and application SSO. [Issuer discovery](https://users.nexusmods.com/.well-known/openid-configuration) advertises authorization code and S256, but is not Marduk's client registration and does not establish allowed native redirects, scopes, token exchange or REST/GraphQL eligibility. Browser authorization and PKCE follow [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252.html) and [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html) if that OAuth route is approved; don't ship another client's registration or a confidential client secret in the app.
- Prefer account-scoped, revalidated update observations and share duplicate catalog reads; honor provider reset/rate-limit signals instead of encoding a help page quota as a permanent API limit. An MD5 lookup may identify candidates, not authorize an install or prove a local payload came from Nexus. Close with provider-reviewed app identity/route and separate free, Premium, expiry, account-action and installed-protocol witnesses. See [Nexus brief](../contracts/m3-nexus-and-versions.md).

## Nexus Collections — M4-S01/S02

- The [public GraphQL schema](https://graphql.nexusmods.com/) documents `collectionRevision` by slug, optional revision, and domain. An omitted revision resolves the latest **published** revision; revision identifiers/status, game versions, schema and external resources are available. Use that as discovery only, then pin and check the returned revision/status; an HTTP success alone is not usable GraphQL data. The query documentation is not a draft/upload/publish commitment.
- The same schema documents `createCollection`, `createOrUpdateRevision`, `publishRevision`, `listCollection` and `unlistCollection`. `createOrUpdateRevision` can replace an existing draft; it is not interchangeable with a create-only call. `publishRevision` names a revision, while list/unlist name a collection. The pinned client actually uses v3 create/revision requests, and its revision path may edit the collection name first (`src/Nexus/nexus_api.py:3975–3999`). Neither the public schema nor the pinned client establishes Marduk eligibility, upload-token semantics, create-only guarantees or safe retry behavior.
- [Collections guidelines](https://help.nexusmods.com/article/115-guidelines-for-collections) distinguish references, external links, and narrowly allowed bundled assets such as tool-generated output; they expressly forbid bundling actual mods or mod files. A local package passing structural checks is not evidence its contents can be sent to Nexus. Show the listing and bundle-rights check before uploading even to a private draft. Do not remove existing local bundle/editor capability to satisfy remote policy. Verify exact export schema, rights, eligible account and separate permissions for draft upload, publish and visibility changes with Nexus before release. See [install](../contracts/m4-collections-install.md) and [authoring](../contracts/m4-collections-authoring.md).

## Thunderstore and Hexium — M3-S03

- Thunderstore's [pinned listing-index implementation](https://github.com/thunderstore-io/thunderstore/blob/fc20b8d2eacc83bc5dbe0784402423fb06e81980/django/thunderstore/repository/api/v1/views/listing_index.py#L14-L19) describes a redirect to a gzip index of gzip chunks. Its [response code](https://github.com/thunderstore-io/thunderstore/blob/fc20b8d2eacc83bc5dbe0784402423fb06e81980/django/thunderstore/repository/api/v1/views/listing_index.py#L63-L83) issues `Last-Modified` and supports `If-Modified-Since`/`304`. Use bounded streaming and promote only complete community snapshots. Here a date validates cached **catalog metadata**; it is not proof for appending mod bytes.
- The [Thunderstore package format](https://github.com/thunderstore-io/thunderstore/blob/fc20b8d2eacc83bc5dbe0784402423fb06e81980/django/thunderstore/repository/templates/repository/package_docs.html) shows exact versioned dependency strings and optional installer declarations. Preserve package-specified identity (including Hexium prerelease suffixes where supported), not highest version by default. Presence of an installer declaration doesn't establish its behavior for any supported game.
- [Hexium's own OpenAPI](https://hexium.gg/api/openapi.json) documents community listing indexes, experimental package lookups and `/api/experimental/legacyprofile/get/{key}/` and `/create/`; the latter stores bytes and is a remote write. A read of a share must still admit and inspect the returned bytes before profile import. Treat the documented compatibility as a wire shape, not a promise of identical conditional responses, installer semantics, package namespaces or fallback. [Hexium terms](https://hexium.gg/legal) prohibit disruptive automation and access/rate-limit evasion. Gale's [adapter source](https://github.com/Kesomannen/gale/blob/2fdda7599840457d11607a02d07cd77346503151/src-tauri/src/thunderstore/backend.rs) is a comparison only; server docs and reviewed fixtures determine Marduk's route. Keep cross-repository dependency fallback distinct from approval to switch an installed mod's source. See [repository brief](../contracts/m3-repository-plans.md).

## Wabbajack — M4-S03

- The pinned [upstream Linux build script](https://github.com/wabbajack-tools/wabbajack/blob/ea2b901a6babdbe73c9d2aab57fcdd8448f276a1/release-linux.sh#L2-L13) and [release workflow](https://github.com/wabbajack-tools/wabbajack/blob/ea2b901a6babdbe73c9d2aab57fcdd8448f276a1/.github/workflows/release.yml#L163-L186) build Linux x64 app/CLI tarballs and attach them after the Windows release. This corrects a Windows-only assumption about **upstream build intent**, not evidence any release artifact was installed, any particular list works, or Marduk should require that launcher.
- Upstream [DTOs](https://github.com/wabbajack-tools/wabbajack/tree/ea2b901a6babdbe73c9d2aab57fcdd8448f276a1/Wabbajack.DTOs/ModList) can help pin manifest shapes, but the [directive directory](https://github.com/wabbajack-tools/wabbajack/tree/ea2b901a6babdbe73c9d2aab57fcdd8448f276a1/Wabbajack.DTOs/ModList/Directives) contains additional types: distinguish installer directives from other serialized/compiler data rather than promising every type or assuming nine is the current upstream total. The [installation guide](https://wiki.wabbajack.org/user_documentation/Installing%20a%20Modlist.html) still requires list-specific instructions. Keep readers, source eligibility, reconstruction, setup and runtime as separate proofs.
- Prefer Rust reconstruction through the existing managed staging and ownership seams. Compare identical inert fixture inputs with a pinned upstream CLI/build or upstream tests after separate approval, not the CLI as a shipped runtime or an unbounded installer. Pin input hash convention separately from local output digests. If format/codec/fixture reuse is proposed, the [upstream license statement](https://github.com/wabbajack-tools/wabbajack/blob/ea2b901a6babdbe73c9d2aab57fcdd8448f276a1/README.md#L70-L72) and [list policy](https://wiki.wabbajack.org/policies_and_license/Wabbajack%20License.html) are inputs to review; code, fixture bytes, list files, game assets and bundled executables need separate provenance and rights. See [Wabbajack brief](../contracts/m4-wabbajack.md).

## mod.io, LoversLab and Workshop — M4-S04

- **mod.io:** The [REST introduction](https://docs.mod.io/restapi/introduction) distinguishes a user/tool or game API path and read-only API-key access (including browsing/downloading) from OAuth account writes. [Larian's announcement](https://baldursgate3.game/news/community-update-27-official-modding-support_118) confirms BG3 uses mod.io and different platform curation, not third-party entitlement to a game-specific API path. Prefer minimum privilege: qualify a legitimate user/tool path and the exact BG3 game/file/platform mapping; qualify a documented compatibility path independently. A sandbox for an authorized test game can exercise wire behavior but cannot prove production BG3 permissions. Do not reuse a game's or another app's key.
- **LoversLab:** At the pinned Wabbajack revision, [LoversLabSource](https://github.com/wabbajack-tools/wabbajack/blob/ea2b901a6babdbe73c9d2aab57fcdd8448f276a1/Wabbajack.Downloaders.ManualSources/LoversLabSource.cs) inherits a [browser-required adapter](https://github.com/wabbajack-tools/wabbajack/blob/ea2b901a6babdbe73c9d2aab57fcdd8448f276a1/Wabbajack.Downloaders.ManualSources/AIPS4Source.cs#L9-L25). The public terms URL was inaccessible from this environment. This establishes a useful modern manual reference, not a site permission grant, and not authority to retire the existing credential-backed capability. Qualify each retained source variant and ask the user before accepting manual-only parity if the direct route cannot be authorized.
- **Workshop:** Steam's [Workshop implementation guide](https://partner.steamgames.com/doc/features/workshop/implementation) separates consumer game App ID from tool or publishing App ID. The [Web API reference](https://partner.steamgames.com/doc/webapi/ISteamRemoteStorage) lists published-file metadata; the [Steamworks UGC SDK](https://partner.steamgames.com/doc/api/ISteamUGC) separately describes client install state. Metadata, a local sidecar, actual Steam installation and byte provenance are different evidence. Keep linking/import/open parity local-first; don't require Steam login or add a Workshop downloader. Optional online metadata verification needs its own eligibility and product review. See [other-provider brief](../contracts/m4-other-providers.md).

## Shared checks that remain open

- [HTTP RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.5) disallows weak ETags for `If-Range`; an HTTP date is only usable if no entity tag is available and it is a strong validator. Qualify reuse by actual provider/representation; if append is not provable, a fresh transfer requires renewed authority for the same reviewed object. Do not carry credentials or old private query parameters into a redirect. See [queue brief](../contracts/m3-download-queue.md).
- [Secret Service](https://specifications.freedesktop.org/secret-service/latest-single/) describes login-session storage, prompting and locking, not its reachability from a given Linux sandbox. [Windows Credential Manager](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw) distinguishes session and same-machine persistence. Qualify install/package/account boundaries with inert credentials separately from provider login; a useful desktop-session check is not a restart or cross-package result. The [secure storage decision](../contracts/m4-other-providers.md#secure-storage-decision) remains open where supported packages lack a usable persistent store.
