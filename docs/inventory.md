# Base-app behavior inventory

**Baseline:** read-only `$LEGACY_PATH`, `08fe1a481747d64278d75a0e1bb36449d158f584`. **Status:** first-pass source inventory, not verified parity. `S` means source-backed at the cited seam; `R` means the public registration or packaging establishes a surface but the behavior still requires tracing. No runtime or shipped-package behavior is claimed here.

Parity is about user outcomes, not old internal formats, UI layout, commands or wire compatibility. MO2 is a Windows research reference only. Game-content plugins (such as `.esp`) are in scope; manager plugin hosting and third-party extensions are not. Bundled behavior remains in scope even if implemented via the host. An adapter-specific outcome is marked with its relevant OS/runtime, not silently removed or assumed identical on both OSes.

The [M2 workspace map](contracts/m2-workspace.md) assigns essential desktop flows to these same IDs. Screens are not extra parity rows: a redesigned screen passes only when its linked outcomes do.

Source names that contain the former product name are described by role, e.g. **headless registry** is `methods.py` in the backend package. All cited paths refer to the pinned tree unless linked to a Marduk document.

## Capability register

Each row has a stable ID, scope, and an acceptance witness. The milestone is the first planned complete slice for that row; earlier milestones can ship a subset. `Retain` is the default except for the exclusions below.

## Exclusions

- **OUT-01:** third-party manager plugin host/store/repository/lifecycle/API compatibility and `plugin-validate`. Audit bundled behavior separately, including any built-in providers implemented through the host. This does not exclude `DATA-01`.
- **OUT-02:** migration and compatibility with the reference's internal schemas, configuration, install trees, debug artifacts or wire contract. Handling user-facing third-party mod list formats (e.g. Wabbajack) and writing tool interoperability data are not migration of the reference app.
- **OUT-03:** OS-specific mechanisms that have no native equivalent (e.g. editing a Wine prefix on native Windows). Track applicability and the underlying user outcome; do not exclude game functionality simply because the old mechanism cannot carry over.
