# M1 Stage A — ZIP, SQLite and native roots

Part of [M1-CORE](../2026-11-21-m1-complete.md). Checkpoint A proves that archive input can become a resolved profile and that the first game can be bound without granting write authority. It does not qualify durable writes.

## ZIP admission (Task 2)

**Owner:** DeepSeek implementation; Sol authors hostile-input acceptance tests; fresh DeepSeek task review. **Files:** `crates/archive/{Cargo.toml,src/lib.rs,src/zip.rs,tests/admission.rs}`. Orchestrator owns registration in root `Cargo.toml` and `Cargo.lock`. A bounded ZIP check may have a private `src/zip/bounds.rs` if separate from the reader adapter.

- [ ] Freeze [C02's archive interface, bounds and error taxonomy](../../../contracts/m1-zip-library.md#archive-interface). Use the contract's `zip` candidate and feature set only if registry, upstream source, current advisories, dependency graph/licensing and native builds check out; record the locked graph. If the candidate fails, stop that dependency and propose an equivalent bounded reader with evidence. No fallback chain or new format.
- [ ] Write the [four named admission witnesses](../../../contracts/m1-zip-library.md#planner-witnesses), including one fully valid golden archive. Fixtures use synthetic headers and inert payloads. Test that over-limit metadata is refused **before** constructing the reader/index, with a counting reader or an observed preflight seam. Check that a conflicting advertised directory or count cannot make the reader enumerate a different set than the bounded check. Assert no payload sink was reached for pre-admission failures.
- [ ] Implement the bounded admission and streaming contract. Reject ambiguity rather than repairing paths. Enumerate by admitted index; enforce expanded byte limits and corruption failure even when headers claim success. Test exact duplicate, case-equivalent file and mixed parent spelling independently. Verify the two admitted fixture bytes and stable typed errors; log neither raw entry names nor absolute paths by default.
- [ ] Run `cargo test --locked -p marduk-archive --test admission`, then workspace format/build/test; record assertion-level red and green, not just compilation. An archive being admissible does not mean it was published to the library.

## SQLite catalog (Task 3)

**Owner:** DeepSeek implementation; Sol authors crash/identity witnesses; fresh DeepSeek reviews. **Files:** `crates/storage/{Cargo.toml,src/lib.rs,src/library.rs,migrations/0001_library.sql,tests/library_contract.rs}`; `crates/core/src/import.rs` and its registration in `lib.rs` own shared import types and the staged payload boundary. Orchestrator owns root manifest and lockfile.

- [ ] Freeze the [C02 library interface and state transitions](../../../contracts/m1-zip-library.md#library-interface-and-state), including opaque import ID, expected profile revision, target kind, exact result on replay and rejected stale IDs. Use native bundled `rusqlite` candidate only after the same dependency checks; choose the smallest verified SHA-256 dependency required by the archive fingerprint, not a second crypto implementation. Bound or reject stored IDs/revisions that cannot round-trip; no unchecked signed/unsigned conversion through SQLite. The shared service consumes typed snapshots and the C01 resolver, not SQL rows.
- [ ] Freeze the test-only stage adapter contract: given an allocation, return an internally issued receipt binding reserved import/revision IDs, archive SHA-256, admitted paths and payload evidence; under the library writer guard, reobserve exact ownership and integrity or report changed/unavailable. An ordinary path, caller assertion or lack of an error is not a receipt. The catalog cannot expose a production `Prepared` import without a qualified stage adapter; a fake may exist only in tests, never a product flag.
- [ ] Author and freeze the [four named catalog witnesses](../../../contracts/m1-zip-library.md#planner-witnesses). Exercise real on-disk SQLite using a fresh fixture database, close/reopen after commit before reply, stale preview (8→9), interruption before publication, and guarded cleanup. Assert old revision bytes, visibility, membership count, operation state and no second increment. Add append-versus-replace assertions: append is last/enabled, Replace retains member ID/order/enablement/name and old payload. Reconciliation refuses to reclaim referenced or ambiguously owned payload.
- [ ] Implement the catalog with a one-time migration, explicit managed writer configuration, and replay check before stale/active checks. Record actual PRAGMA results. Work against test-issued stage evidence until Task 5 can issue native evidence. Run `cargo test --locked -p marduk-storage --test library_contract` and workspace checks. Output a working prepared/published/replayed fixture with SQLite, not a claim about real bytes surviving power loss.

## Game and root authority (Task 4)

**Owner:** Sol freezes the trust boundary and authors acceptance cases; DeepSeek implements shared layout and each OS adapter; independent DeepSeek task review plus Sol gate review. **Files:** `crates/core/src/root_identity.rs`, its `lib.rs` registration, `crates/games/{Cargo.toml,src/lib.rs,src/skyrim_se.rs,tests/skyrim_se.rs}`, `crates/platform/{Cargo.toml,src/lib.rs,src/linux.rs,src/windows.rs,tests/root_contract.rs}`; orchestrator registers crates and updates lockfile. Keep platform-specific modules and test helpers within those crate boundaries.

- [ ] Freeze [R01 operations, errors and proof types](../../../contracts/m1-root-verification.md). Derive an opaque persistable identity from the opened object, not path text; the live authority is a different type and cannot be reconstructed from a token. Keep errors and root roles portable. The approved game module declares `Data` and the inert `SkyrimSELauncher.exe`/`SkyrimSE.exe` marker witness; platform consumes a neutral descriptor or bounded observations and never branches on Skyrim SE. No auto-discovery, launch, DLL tooling, external-root traversal or actual installed game binaries.
- [ ] Freeze Linux and Windows native APIs on current system documentation and named dependencies. Use directory-relative/handle verification, no-follow and the per-filesystem identity rules: Linux includes approved mount boundary and Btrfs subvolume identity; Windows uses volume and native file identity plus reparse refusal. Do not pretend a compile-only platform module, lexical containment check, or metadata from an unopened path qualifies an effect. Report exact handling of unsupported cases; changes that narrow a retained configuration require an explicit decision.
- [ ] Author the [five R01 witnesses](../../../contracts/m1-root-verification.md#planner-witnesses) and a valid synthetic marker/layout fixture. Capture separate installation/Data identity, preserve existing spelling, refuse root substitution and actual junction/symlink when supported, and distinguish missing parent from verified absence. Linux aliases and Btrfs same-inode substitution require the named configuration; do not mark a test green by skipping the mutation that makes it meaningful. All probes read only the synthetic layout; record a sentinel before/after.
- [ ] Run `cargo test --locked -p marduk-games --test skyrim_se`, `cargo test --locked -p marduk-platform --test root_contract`, and workspace checks. Record OS, filesystem/driver, scenario results, and missing environments. Platform checked only on one environment neither qualifies another nor authorizes deployment.

**Checkpoint A:** list archive, catalog, and root results separately. ZIP and fault-tested catalog can pass while native payload qualification or one root case is pending. Task 5 consumes only root evidence actually obtained. Task 6 can proceed on a deterministic adapter without a native pass.
