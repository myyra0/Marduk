# M1 Stage C — CLI, desktop and C1 qualification

Part of [M1-CORE](../2026-11-21-m1-complete.md). Checkpoint C joins clients to one service and owns the final distinction between a working synthetic workflow and a verified M1.

## CLI and desktop (Task 7)

**Owners:** DeepSeek builds shared composition and clients, with independent task review; Sol reviews authority and transport boundaries. **Files:** `crates/workspace/{Cargo.toml,src/lib.rs,tests/workflow.rs}` for shared assembly; `crates/cli/{Cargo.toml,src/main.rs,tests/workflow.rs}` for CLI; `app/` for desktop frontend, Tauri code, tests and lockfiles. Orchestrator owns the shared Cargo manifest/lockfile and `.github/workflows/m1.yml`; extend existing proof jobs with native desktop checks. No installer distribution, updater or secrets.

- [ ] Freeze [U01 operations and wire rules](../../../contracts/m1-clients.md) and the app stack from the parent brief. Use one `marduk-workspace` assembly because there are two clients; it composes the same engine/adapters, not a second implementation of resolution/transactions. Freeze request/result fields and stable code mapping with Rust-serialized fixtures for IDs above `2^53`. Use the CLI command names in the contract, stable exit `0` for success and `1` for rejected/failed operations (`2` for parse/usage); `--json` serializes the same IDs, structured codes and results. A blocked route returns an explicit typed unavailable reason, not “simulated success.”
- [ ] Author and freeze all [seven U01 witnesses](../../../contracts/m1-clients.md#acceptance). Separate test-only frontend and shared-service fixtures from real service composition. Assert DTO exactness over `2^53`, stale preview after reorder, lost event/replay without a second mutation, Restore conflict, keyboard focus/selection, and absence of generic shell/file writes. Include exact selected ZIP identity and profile revision in import preview/apply checks.
- [ ] Keep local Tauri commands capability-scoped to the trusted window. Start with an official Dialog picker for game folder and ZIP only; allow open, not broad filesystem/write/shell commands. Treat the returned selection as input requiring Rust validation. Use a restrictive CSP, local assets, typed Rust-backed transport and ordered progress plus authoritative status refresh. No raw OS paths in default diagnostics unless needed for the current authorized selection.
- [ ] Build one workspace view: selection/status, ZIP preview and explicit import apply, mod list low-to-high, keyboard reorder by membership ID, conflict winner/target/backup status, explicit deployment review, Apply and Restore. On restart/disconnect reload authoritative state, never blindly repeat a write; show conflict/retained backup without claiming restored. Frontend tests may use a test-only service fixture. Product code must never gain mutation authority from a UI flag, archive, path text or fixture label.
- [ ] Run `cargo test --locked -p marduk-workspace --test workflow`, `cargo test --locked -p marduk-cli --test workflow`, then workspace checks. Keep `app/src-tauri` a separate Cargo workspace with its own lockfile and path dependencies on the Rust service, so missing webview prerequisites do not block core tests. Use `npm ci`, `npm run test`, `npm run build`, and `npm run tauri build` in `app/`; record versions, scripts and prerequisites per runner. Use Tauri WebDriver with WebKitWebDriver/compatible Edge driver for native smoke. Workflow uses the existing runner labels, locked installs and read-only permissions; verify full action SHAs, non-persisted credentials, and no publish steps.

## C1 proof and handoff (Task 8)

**Owners:** Sol defines the oracle and gives final independent review; DeepSeek implements the fixture driver and collects evidence. **Files:** `tests/platform/m1/`, `docs/research/m1-native-results.md`, `.github/workflows/m1.yml` if CI launches an approved fixture case. Not a new production feature or an authorization to change runner settings.

- [ ] Drive the [golden fixture](../../../research/recovery-oracle.md#golden-fixture) end-to-end in both clients with the actual shared engine and qualified scratch adapters: import A and B, `[A,B]` previews B, `[B,A]` previews A, then use `[A,B]` for the golden deploy. Check `winner.dds = b\n`, `a-only.dds = only-a\n`; Restore returns `base\n`, removes only the unchanged managed-created file, preserves `keep\n`, and does not mutate source payloads. A second Restore is a no-op. Negative cases demonstrate stale plan, missing parent, wrong root and preserved external `edit\n` plus backup. Keep fixture and unqualified product paths separate.
- [ ] Execute actual child-process cuts from the [recovery oracle](../../../research/recovery-oracle.md#evidence-separation) at meaningful prepare/publish/finalize/Restore transitions. Reopen the same owned fixture and independently verify names, bytes, supported metadata, journal status and repeated recovery. Record native Linux ext4, Linux Btrfs (including separate subvolumes), and Windows NTFS independently. A test that skips its required cut or runs against the wrong filesystem is `not run`, not success.
- [ ] Gate separately on approved disposable VM power-off runs and authorized Skyrim SE loose-asset smoke on the applicable Linux/Windows runtime routes. Do not provision VMs, force power-off, touch real game files or start a game without separate consent and the precise configuration. A hosted packaged run and deterministic simulation are not that evidence. Resume at these gates if they are all that remain.
- [ ] Verify the reviewed final SHA across both hosts: workspace checks, distinct native package smoke and configuration-specific recovery evidence. Have a fresh Sol reviewer evaluate the approved scopes, combined diff, frozen tests and evidence before reading earlier verdicts; resolve blocking findings within project cycle limits. C1 is verified only when every retained M1 exit witness has evidence. Fixes and offline passes can land as a reviewable local branch while a proof gate remains open.

**Checkpoint C:** report exact SHA, native/client/proof status, real blockers and the safe next action. Do not begin M2, start a hostile-environment probe, or call missing evidence a product limitation the user agreed to.
