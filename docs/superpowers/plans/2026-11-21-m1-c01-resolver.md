# M1-C01 Logical File Resolution Implementation Plan

> **For agentic workers:** Execute with `subagent-driven-development` after user approval and preflight. Follow `AGENTS.md` for exact model bindings, review and escalation.

**Goal:** Turn an ordered profile and installed-file manifests into deterministic loose-file winners and provenance, or a typed error.

**Architecture:** Pure Rust core. Validate portable logical paths independently of native placement. Resolve by profile order, with a canonical logical key and original spelling retained for the winning file and each candidate.

**Tech stack:** Rust `stable`, Cargo, standard library only.

**Spec:** [M1-C01 contract](../../contracts/m1-file-resolution.md). **Status:** `draft` until the launch prompt approves this brief and contract and the independent preflight passes.

## Review Focus

- Wrong winner when member or revision IDs sort differently from profile order; reverse the profile and check exact provenance and revision.
- Ignoring the disabled bit, or deduplicating by installed revision instead of membership; test missing and present disabled manifests and distinct members of one revision.
- Confusing case aliases within a manifest with legal conflict across mods; test exact duplicates, case aliases and the winning spelling.
- Treating a directory stem as a file-path prefix or ignoring an ancestor conflict; the same two inputs in both orders must fail, and a similar sibling must succeed.
- Normalizing an unadmitted path or reporting the wrong component; test the first bad component and untouched valid spelling.
